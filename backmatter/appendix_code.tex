\section{Centre of Compliance and the Offset Adjoint}
\label{app:center_compliance}

The thesis defines the compliance-centre displacement as
\(r_c=p_c-p_{\mathrm{TCP}}\), which points from the TCP to the selected
centre of compliance. The controller source uses the opposite vector
internally, \(\ell_c=p_{\mathrm{TCP}}-p_c=-r_c\).

In \mbox{\Cref{lst:app_compliance_adjoint,lst:app_spring_wrench}}, the code
identifier \texttt{r\_c} represents this internal lever \(\ell_c\), not the
thesis quantity \(r_c\). The upper-right block of the source-side point-shift
matrix is therefore \([\ell_c]_\times=-[r_c]_\times\), which is the
upper-right block of the adjoint defined in
\mbox{\Cref{eq:offset_adjoint}}. The same congruence transformation is
applied to the Cartesian stiffness and damping matrices.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Source-side compliance-centre adjoint and congruence transform.}, label={lst:app_compliance_adjoint}]
Mat3 skewMatrix(const Vec3& v) {
  Mat3 s;
  s << 0.0, -v(2),  v(1),
       v(2),  0.0, -v(0),
      -v(1),  v(0),  0.0;
  return s;
}

Mat6x6 complianceShiftMatrix(const Vec3& r_c) {
  Mat6x6 adjoint = Mat6x6::Zero();
  adjoint.block<3, 3>(0, 0) = Mat3::Identity();
  adjoint.block<3, 3>(0, 3) = skewMatrix(r_c);
  adjoint.block<3, 3>(3, 3) = Mat3::Identity();
  return adjoint;
}

Mat6x6 shiftGainToTcp(
    const Mat6x6& gain_at_center, const Vec3& r_c) {
  const Mat6x6 adjoint = complianceShiftMatrix(r_c);
  return adjoint.transpose() * gain_at_center * adjoint;
}
\end{lstlisting}

\begin{sloppypar}
The tool-frame parameter \texttt{compliance\_center\_offset\_ee} stores the
thesis displacement \(r_c\) in end-effector coordinates, and the controller
negates it when constructing the internal lever \(\ell_c\). The alternative
surface-frame parameter
\texttt{r\_tcp\_from\_compliance\_center\_surface} stores \(\ell_c\)
directly. All non-zero \abbr{CoC} displacements used in the experiments were
configured through the tool-frame definition.
\end{sloppypar}

\mbox{\Cref{lst:app_spring_wrench}} shows how the controller selects between
the block-diagonal impedance at the TCP and the point-shifted impedance about a
displaced centre of compliance.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Selection of the decoupled or coupled spring wrench (abridged).}, label={lst:app_spring_wrench}]
const bool coupled =
    params.use_virtual_compliance_center &&
    (state == ControlState::kContactEstablishment ||
     state == ControlState::kPreGrindingHold ||
     (state == ControlState::kPoseHold &&
      params.use_contact_impedance_hold));
if (!coupled) {
  // Two independent springs. dv.tail is -omega, so the damping
  // signs match.
  Vec6 wrench;
  wrench.head<3>() = Kp * dx.head<3>() + Dp * dv.head<3>();
  wrench.tail<3>() = KR * dx.tail<3>() + DR * dv.tail<3>();
  return wrench;
}

Vec3 r_c = Vec3::Zero();
if (params.compliance_center_in_tool_frame) {
  r_c = -(R_EE * params.compliance_center_offset_ee);
} else {
  r_c = R_base_surface *
      params.r_tcp_from_compliance_center_surface;
}
const Mat6x6 K_tcp =
    shiftGainToTcp(blockDiagonal(Kp, KR), r_c);
const Mat6x6 D_tcp =
    shiftGainToTcp(blockDiagonal(Dp, DR), r_c);
return K_tcp * dx + D_tcp * dv;
\end{lstlisting}


\section{Final Torque Assembly}
\label{app:callback_core}

\Added{\mbox{\Cref{lst:implementation_pose_error}} shows how the callback
combines the Cartesian impedance wrench, the null-space torque, the
experiment-specific disturbance, and the model Coriolis contribution into the
commanded joint torque of
\mbox{\Cref{eq:nullspace_complete_torque_command}}. The acquisition of the
measured joint state, the Jacobian and the end-effector pose is standard
libfranka usage and is described in
\mbox{\Cref{sec:software_architecture}}.}

\begin{lstlisting}[style=cppstyle, language=C++, caption={Final joint-torque assembly (abridged).}, label={lst:implementation_pose_error}]
const Vec6 wrench =
    computeCartesianImpedanceWrench(
        params, state, Kp_used, Dp_used,
        KR_used, DR_used, R_base_surface,
        dx, dv, R_EE);

const Vec7 tau_nullspace = computeNullspaceTorque(
    params, model, state, J, dq);

const Vec7 tau_task = J.transpose() * wrench;
const Vec7 tau_cmd =
    tau_task + tau_nullspace + disturbance.tau + coriolis;
\end{lstlisting}

\Added{The Cartesian pose-hold study of
\mbox{\Cref{sec:nullspace_hold_study}} activates the disturbance term. In the
surface-contact experiments this contribution is zero.}
