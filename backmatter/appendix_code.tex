\section{Surface Task Frame and Spatial Gains}
\label{app:surface_gains}

The frame order is \([t_1,t_2,n_s]\).  Because
\(t_2=n_s\times t_1\), this column order is right-handed. A configured tangent
that is close to the surface normal \(n_s\) is replaced by a fallback direction, so the frame
stays defined for any configured plane.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Surface frame and gain transformation used by the controller.}, label={lst:app_surface_gains}]
Mat3 makeSurfaceFrameFromNormalTangent(
    const Vec3& normal_input, const Vec3& tangent1_input) {
  const Vec3 normal =
      normalizedOrFallback(normal_input, Vec3(1.0, 0.0, 0.0));
  Vec3 tangent1 =
      tangent1_input - normal * normal.dot(tangent1_input);

  if (tangent1.norm() <= 1e-9) {
    Vec3 fallback(0.0, 1.0, 0.0);
    if (std::abs(normal.dot(fallback)) > 0.95) {
      fallback = Vec3(0.0, 0.0, 1.0);
    }
    tangent1 = fallback - normal * normal.dot(fallback);
  }

  tangent1.normalize();
  Vec3 tangent2 = normal.cross(tangent1);
  tangent2.normalize();

  Mat3 R_base_surface;
  R_base_surface.col(0) = tangent1;
  R_base_surface.col(1) = tangent2;
  R_base_surface.col(2) = normal;
  return R_base_surface;
}

Mat3 makeSpatialGainMatrix(
    const Vec3& diagonal_in_task_frame, const Mat3& R_task) {
  return R_task * diagonal_in_task_frame.asDiagonal()
       * R_task.transpose();
}
\end{lstlisting}

\section{Tool Orientation and Rotation Error}
\label{app:orientation}

The physical tool axis \(a_{\mathrm{EE}}\) is configured in the EE frame. The desired orientation
is the minimum rotation of the captured start orientation that maps this axis
onto the signed normal; it is not obtained by assigning the complete surface
frame to the EE frame. The commanded angular offsets of a case are applied to
that axis before the rotation is formed. A commanded tool orientation offset
about \(t_1\) or \(t_2\) therefore enters as a rotation of the orientation target
rather than as a trajectory.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Tool-axis target, commanded tool orientation offsets, and rotation-vector error.}, label={lst:app_orientation}]
Vec3 surfaceToolAxisInBase(
    const ControllerConfig& params, const Mat3& R_base_surface) {
  const double sign =
      (params.tool_axis_target_sign >= 0.0) ? 1.0 : -1.0;
  return sign * R_base_surface.col(2);  // normal = 3rd column
}

Vec3 desiredToolAxisInBase(
    const ControllerConfig& params, const Mat3& R_base_surface) {
  const Vec3 flat_axis =
      surfaceToolAxisInBase(params, R_base_surface);
  const double deg_to_rad = M_PI / 180.0;
  const Vec3 rotation_vector =
      deg_to_rad *
      (params.tool_target_offset_tangent1_deg
           * R_base_surface.col(0) +
       params.tool_target_offset_tangent2_deg
           * R_base_surface.col(1));
  const double angle = rotation_vector.norm();
  if (angle <= 1e-12) {
    return flat_axis;
  }
  return Eigen::AngleAxisd(angle, rotation_vector / angle)
       * flat_axis;
}

Vec3 orientationError(
    const Mat3& R_current, const Mat3& R_desired) {
  Mat3 R_error = R_current.transpose() * R_desired;
  Eigen::AngleAxisd angle_axis(R_error);
  if (std::abs(angle_axis.angle()) < 1e-9) {
    return Vec3::Zero();
  }
  return R_current * angle_axis.axis() * angle_axis.angle();
}
\end{lstlisting}

The shortest arc that carries the current tool axis onto the target turns about
an axis perpendicular to the tool axis, so it leaves the spin about that axis at
whatever the start pose held. That spin decides which edge of a rectangular
face leads into the surface, so it is commanded separately through
\texttt{tool\_target\_offset\_normal\_deg} rather than inherited from
\(q_{\mathrm{init}}\).

\begin{lstlisting}[style=cppstyle, language=C++, caption={Commanded spin about the tool axis (abridged).}, label={lst:app_tool_twist}]
const Mat3 R_axis =
    rotationBetweenUnitVectors(tool_axis_start, tool_axis_target)
    * R_start;
if (!params.command_tool_twist) {
  return R_axis;
}

// Both directions are measured in the plane perpendicular to the
// tool axis.
const Vec3 current = perpendicular(R_axis * face_long_axis_ee);
const Vec3 zero_reference =
    perpendicular(R_base_surface.col(0));
if (current.norm() <= 1e-9 || zero_reference.norm() <= 1e-9) {
  return R_axis;  // no twist is defined
}

const Vec3 target =
    Eigen::AngleAxisd(
        (M_PI / 180.0) * params.tool_target_offset_normal_deg,
        tool_axis_target)
    * zero_reference.normalized();
const Vec3 current_unit = current.normalized();
double twist = std::atan2(
    tool_axis_target.dot(current_unit.cross(target)),
    current_unit.dot(target));

// A face centred on the tool axis maps onto itself every half turn,
// so take the representative nearest the start pose.
if (face_center_off_axis.norm() <= 0.05 * face_scale) {
  twist -= M_PI * std::round(twist / M_PI);
}
return Eigen::AngleAxisd(twist, tool_axis_target) * R_axis;
\end{lstlisting}

\section{Geometric Clearance and Phase Targets}
\label{app:desired_motion}

The leading point, edge, or face of the rectangular tool is selected along the
descent direction. The transition into set-up is based on the exact
most-leading corner height; the average of corners tied within
\(0.1\,\mathrm{mm}\) supplies the controlled contact point and projected reference.
The transition depends on this height; the external-force estimate does not
enter the decision. The following excerpt is abridged from the phase switch.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Phase-dependent tool-feature targets (abridged).}, label={lst:app_desired_motion}]
const Vec3 descend_direction = -R_base_surface.col(2);
double leading_contact_projection = 0.0;
const Vec3 tool_contact_offset_ee =
    selectLeadingToolContact(R_EE, leading_contact_projection);
const Vec3 tool_contact_point =
    p_EE + R_EE * tool_contact_offset_ee;

case ControlPhase::kSurfaceApproach: {
  // The gate freezes this clock, so waiting does not go on ramping
  // the commanded distance.
  const double distance = std::min(
      params.descend_speed * (phase_time - gate_paused_time),
      params.descend_max_distance);
  desired.p_d = p_start + distance * descend_direction;
  desired.pdot_d = params.descend_speed * descend_direction;

  const Vec3 surface_normal = (-descend_direction).normalized();
  const double height_above_surface =
      surface_normal.dot(p_EE - surface_point_runtime)
      - leading_contact_projection;
  const double controlled_point_height =
      surface_normal.dot(tool_contact_point - surface_point_runtime);
  const Vec3 projected_surface_point =
      tool_contact_point - controlled_point_height * surface_normal;
  const bool clearance_reached =
      height_above_surface <= params.descend_surface_clearance;

  if (clearance_reached && !gate_blocking) {
    active_tool_contact_offset_ee = tool_contact_offset_ee;
    first_contact_tcp = p_EE;  // captured at clearance
    first_contact_point = projected_surface_point;
    setup_push_start = -controlled_point_height;
    R_contact_start = R_EE;
    contact_force_bias = external_force;
    contact_moment_bias = external_moment;
    phase = ControlPhase::kSetup;
  }
  break;
}

case ControlPhase::kSetup: {
  const double push =
      setUpPush(params, phase_time - gate_grind_paused_time,
                setup_push_start, setup_push_velocity);
  const Vec3 edge_target =
      first_contact_point + push * descend_direction;
  desired.p_d =
      edge_target - R_contact_start * tool_contact_offset_ee;
  desired.pdot_d = setup_push_velocity * descend_direction;
  // Exit after minimum time on moment-delta norm, or on timeout.
  break;
}

case ControlPhase::kGrinding: {
  const Vec3 n = descend_direction;  // unit, into the surface
  Vec3 edge_target;
  if (params.grind_sweep_enabled) {
    edge_target = first_contact_point + grind_push * n
                + sweep_s * grind_tangent;
    desired.pdot_d = sweep_s_dot * grind_tangent;
  } else {
    const double edge_penetration =
        n.dot(tool_contact_point - first_contact_point);
    edge_target =
        tool_contact_point + (grind_push - edge_penetration) * n;
  }
  desired.p_d =
      edge_target - R_contact_start * tool_contact_offset_ee;
  break;
}
\end{lstlisting}

The identifiers \texttt{first\_contact\_*} are retained source names. They are
captured at the configured clearance, not at a force-detected first contact.
The model-estimated wrench recorded at the same instant is subtracted from
every later sample.

Both operator gates latch once armed. The gate compares a held pose against the
clearance height, and re-testing that comparison every cycle released the gate
for single cycles on measurement noise; on each release the descent clock
advanced and commanded the tool further down, so a longer wait produced a
harder press. Latching removes that dependence on waiting time.

\section{Centre of Compliance and the Offset Adjoint}
\label{app:center_compliance}

The lever \(r_c\) passed to the implementation points from the selected centre of
compliance \(p_c\) to the TCP:
\[
r_c=p_{\mathrm{TCP}}-p_c.
\]
The same congruence is applied to stiffness and damping.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Pole-to-TCP adjoint and congruence transform.}, label={lst:app_compliance_adjoint}]
Mat3 skewMatrix(const Vec3& v) {
  Mat3 s;
  s << 0.0, -v(2),  v(1),
       v(2),  0.0, -v(0),
      -v(1),  v(0),  0.0;
  return s;
}

Mat6x6 complianceShiftMatrix(const Vec3& r_c) {
  Mat6x6 adjoint = Mat6x6::Zero();
  adjoint.block<3, 3>(0, 0) = Mat3::Identity();
  adjoint.block<3, 3>(0, 3) = skewMatrix(r_c);
  adjoint.block<3, 3>(3, 3) = Mat3::Identity();
  return adjoint;
}

Mat6x6 shiftGainToTcp(
    const Mat6x6& gain_at_center, const Vec3& r_c) {
  const Mat6x6 adjoint = complianceShiftMatrix(r_c);
  return adjoint.transpose() * gain_at_center * adjoint;
}
\end{lstlisting}

The wrench routine selects between the decoupled and the coupled law and
constructs the lever. The centre can be defined relative to the TCP in
end-effector coordinates, or the lever can be given directly in surface
coordinates. Both definitions use the convention
\(r_c=p_{\mathrm{TCP}}-p_c\).

\begin{lstlisting}[style=cppstyle, language=C++, caption={Selection of the decoupled or coupled spring wrench (abridged).}, label={lst:app_spring_wrench}]
const bool coupled =
    params.use_virtual_compliance_center &&
    (phase == ControlPhase::kSetup ||
     (phase == ControlPhase::kPoseHold &&
      params.use_setup_impedance_hold));
if (!coupled) {
  // Two independent springs. dv.tail is -omega, so the damping
  // signs match.
  Vec6 wrench;
  wrench.head<3>() = Kp * dx.head<3>() + Dp * dv.head<3>();
  wrench.tail<3>() = KR * dx.tail<3>() + DR * dv.tail<3>();
  return wrench;
}

Vec3 r_c = Vec3::Zero();
if (params.compliance_center_in_tool_frame) {
  r_c = -(R_EE * params.compliance_center_offset_ee);
} else {
  r_c = R_base_surface
      * params.r_tcp_from_compliance_center_surface;
}
const Mat6x6 K_tcp =
    shiftGainToTcp(blockDiagonal(Kp, KR), r_c);
const Mat6x6 D_tcp =
    shiftGainToTcp(blockDiagonal(Dp, DR), r_c);
return K_tcp * dx + D_tcp * dv;
\end{lstlisting}

\section{Task-Inertia Damping}
\label{app:auto_damping}

The joint-space mass matrix \(M\) is solved rather than explicitly inverted.
A \(10^{-9}\) diagonal regularisation is used only for the task-inertia
matrix \(\Lambda\)
calculation; it is not the null-space pseudoinverse cutoff. Every intermediate
result is checked before use, and a single non-finite or non-positive entry
marks the estimate invalid.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Task-inertia estimate and per-axis damping (abridged).}, label={lst:app_auto_damping}]
Eigen::LDLT<Mat7x7> mass_ldlt(joint_mass);
const Mat7x6 Minv_Jt = mass_ldlt.solve(J.transpose());
Mat6x6 lambda_inv = J * Minv_Jt;
lambda_inv = 0.5 * (lambda_inv + lambda_inv.transpose());

Mat6x6 lambda_inv_damped = lambda_inv;
lambda_inv_damped.diagonal().array() += 1e-9;
Eigen::LDLT<Mat6x6> lambda_ldlt(lambda_inv_damped);
Mat6x6 Lambda_base = lambda_ldlt.solve(Mat6x6::Identity());
Lambda_base = 0.5 * (Lambda_base + Lambda_base.transpose());

const Mat6x6 T_task = blockDiagonalRotation(R_task);
Mat6x6 Lambda_task = T_task.transpose() * Lambda_base * T_task;
Lambda_task = 0.5 * (Lambda_task + Lambda_task.transpose());

for (int i = 0; i < 3; ++i) {
  const double m = Lambda_task(i, i);
  const double I = Lambda_task(i + 3, i + 3);
  if (m <= 0.0 || I <= 0.0) {
    return result;  // estimate stays invalid
  }
  result.translational(i) = m;
  result.rotational(i) = I;
}

Vec3 criticalDampingFromStiffness(const Vec3& inertia,
                                  const Vec3& stiffness,
                                  double damping_ratio,
                                  const Vec3& min_damping,
                                  double max_damping) {
  Vec3 damping = Vec3::Zero();
  const double zeta = std::max(0.0, damping_ratio);
  for (int i = 0; i < 3; ++i) {
    const double m = std::max(0.0, inertia(i));
    const double k = std::max(0.0, stiffness(i));
    const double critical = 2.0 * zeta * std::sqrt(m * k);
    damping(i) = std::min(
        max_damping,
        std::max(std::max(0.0, min_damping(i)), critical));
  }
  return damping;
}
\end{lstlisting}

Only finite, positive directional inertia values \(\lambda_i\) are used. Otherwise, the
phase-specific fixed damping matrix \(D\) is applied. Each inertia-scaled coefficient
is bounded above by \texttt{auto\_damping\_max}; the value configured for the
reported experiments is listed in \Cref{app:controller_parameters}. The lower
bound \texttt{min\_damping} is the configured manual matrix only when
\texttt{auto\_damping\_min\_from\_manual} is set, and is zero otherwise.

\section{Null-Space Torque}
\label{app:nullspace}

For \(J\in\mathbb R^{6\times7}\), Eigen returns six singular values and a full
\(7\times7\) right-singular matrix.  Column six in zero-based C++ indexing is
therefore \(v_7\), the structural null vector; it is distinct from \(v_6\), the
right-singular vector paired with \(\sigma_{\min}=\sigma_6\). The two sampled
configurations are evaluated by re-querying the robot model for the Jacobian
\(J(q_\pm)\) at \(q\pm\alpha n\), so the comparison uses the same kinematics as the control
cycle.

\begin{lstlisting}[style=cppstyle, language=C++, caption={Thresholded-SVD joint-torque projector and null-space law (abridged).}, label={lst:app_nullspace}]
Eigen::JacobiSVD<Mat6x7> svd_current(
    J, Eigen::ComputeFullU | Eigen::ComputeFullV);
const auto singular_values = svd_current.singularValues();
const double svd_cutoff =
    std::max(0.0, params.nullspace_svd_relative_tolerance)
    * singular_values.maxCoeff();

Mat7x6 J_pinv = Mat7x6::Zero();
for (int i = 0; i < 6; ++i) {
  if (singular_values(i) > svd_cutoff) {
    J_pinv += (1.0 / singular_values(i))
            * svd_current.matrixV().col(i)
            * svd_current.matrixU().col(i).transpose();
  }
}

Mat7x7 N_tau =
    Mat7x7::Identity() - J.transpose() * J_pinv.transpose();
N_tau = 0.5 * (N_tau + N_tau.transpose());
const Vec7 dq_nullspace = N_tau * dq;

// Mode 0 commands nothing, but the projector above still observes
// the redundant axis for the diagnostics.
if (params.nullspace_mode == NullspaceMode::kOff) {
  return Vec7::Zero();
}

const bool damping_enabled =
    params.nullspace_mode == NullspaceMode::kDampingOnly ||
    params.nullspace_mode == NullspaceMode::kDampingAndSigma;
Vec7 tau_damping = Vec7::Zero();
if (damping_enabled) {
  tau_damping.noalias() =
      -params.nullspace_damping * dq_nullspace;
}
if (params.nullspace_mode == NullspaceMode::kDampingOnly) {
  return tau_damping;
}
const bool sigma_only =
    params.nullspace_mode == NullspaceMode::kSigmaOnly;
const Vec7 sigma_fallback = sigma_only ? Vec7::Zero() : tau_damping;

Vec7 n = svd_current.matrixV().col(6);       // v_7
if (n.norm() <= 1e-9) { return sigma_fallback; }
n.normalize();
const double alpha =
    std::abs(params.nullspace_probe_step_rad);
if (alpha <= 1e-12) { return sigma_fallback; }

// The Jacobian is re-evaluated at the two sampled configurations.
Map<const Mat6x7> J_plus(model.zeroJacobian(
    Frame::kEndEffector, vec7ToArray(Vec7(q_current + alpha * n)),
    state.F_T_EE, state.EE_T_K).data());
Map<const Mat6x7> J_minus(model.zeroJacobian(
    Frame::kEndEffector, vec7ToArray(Vec7(q_current - alpha * n)),
    state.F_T_EE, state.EE_T_K).data());

const double sigma_difference =
    smallestSingularValue(J_plus) - smallestSingularValue(J_minus);
const double deadband =
    std::max(0.0, params.nullspace_sigma_deadband);
if (std::abs(sigma_difference) <= deadband) {
  return sigma_fallback;
}

const double sigma_direction = (sigma_difference > 0.0) ? 1.0 : -1.0;
const Vec7 best_direction = sigma_direction * n;
// alpha determines only where sigma is sampled. k_sigma is the
// commanded torque magnitude along the better direction.
const Vec7 tau_sigma =
    params.nullspace_sigma_gain * N_tau * best_direction;

return sigma_only ? tau_sigma : tau_damping + tau_sigma;
\end{lstlisting}

Here the code variable \texttt{alpha} represents
\(\alpha_{\mathrm{probe}}\) and changes only the two sampled configurations.
It does not multiply the active torque. Singular values at or below the cutoff
are omitted from the inverse. The routine also fills a diagnostics structure
that carries the sampled singular values, the selected direction, and the
projected joint velocity \(\dot q_{\mathrm{null}}\) into the recorded data.

\section{Core Control Callback}
\label{app:callback_core}

\begin{lstlisting}[style=cppstyle, language=C++, caption={Core impedance, coupled set-up, and torque composition.}, label={lst:app_callback_core}]
const Vec3 e_p = desired.p_d - p_EE;
const Vec3 e_R = applyRotationalAxisMask(
    params, orientationError(R_EE, R_d_used), R_base_surface);

Vec6 dx;
dx.head<3>() = e_p;
dx.tail<3>() = e_R;
Vec6 dv;
dv.head<3>() = desired.pdot_d - pdot;
dv.tail<3>() = -omega;

const Vec6 wrench =
    computeCartesianImpedanceWrench(
        params, phase, Kp_used, Dp_used,
        KR_used, DR_used, R_base_surface,
        dx, dv, R_EE);

const Vec7 tau_nullspace = computeNullspaceTorque(
    params, model, state, D, dq);

AutomaticDisturbance disturbance;
if (phase == ControlPhase::kPoseHold &&
    params.disturbance_auto_enabled) {
  disturbance = computeAutomaticDisturbance(
      params, model, state, disturbance_force_direction_base,
      time - phase_start_time);
}

Array7 coriolis_array = model.coriolis(state);
Map<const Vec7> coriolis(coriolis_array.data());
const Vec7 tau_task = J.transpose() * wrench;
const Vec7 tau_cmd =
    tau_task + tau_nullspace + disturbance.tau + coriolis;
\end{lstlisting}

The null-space function is called in every non-manual phase. Manual guidance
uses its separate Coriolis-plus-joint-damping branch. The disturbance term is
non-zero only in the Cartesian pose-hold study of
\Cref{sec:nullspace_hold_study}; it is zero in every surface-contact run.
