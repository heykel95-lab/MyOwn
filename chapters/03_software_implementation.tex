\section{Controller Architecture and Real-Time Control Cycle}
\label{sec:software_architecture}
\label{sec:real_time_control_loop}

The software separates configuration and operator interaction from the
real-time control calculation and from subsequent data processing. The complete
parameter set is read and validated before a controller session starts, so the
real-time callback receives the prepared configuration, preallocated
state, the robot-model interface, and non-blocking operator requests. File
output and experiment evaluation are performed after torque control has stopped.

At program start the \mbox{\abbr{FCI}} connection is established, error
recovery is requested, the selected collision behaviour is applied, and the
robot model is loaded. A separate keyboard thread receives operator requests
and transfers them through atomic variables, which keeps terminal input outside
the real-time callback. Reading and validating the configuration again before
each session permits parameter-file changes between experiments.

The operating-state flow begins with robot recovery and controller selection,
as shown in \mbox{\Cref{fig:controller_state_flow}}. A successful recovery
opens the selection state. Inputs \texttt{s}, \texttt{h}, \texttt{t}, and
\texttt{g} select the surface-contact sequence, Cartesian pose hold,
Contact-Impedance Hold, and Manual Guidance, respectively. An unsuccessful
recovery ends the program. Operator stop, a configured experiment-duration
limit, a robot-side error or reflex, and a communication or control exception
provide the common transition from any active controller state to Stop.

\Added{Libfranka reports robot-side errors and reflexes across its monitored
conditions. By contrast, communication and control exceptions form the
application-side category.}

Contact-Impedance Hold retains the captured Cartesian pose with the impedance
used for Contact Establishment. Its connection to the surface-contact sequence
is shown in \mbox{\Cref{fig:phase_flow_chart}}.

\mbox{\Cref{fig:controller_block_diagram}} presents one callback as a closed
Cartesian feedback loop. The active controller state supplies the desired
reference \mbox{\(p_d\)}, \mbox{\(R_d\)}, and \mbox{\(\dot p_d\)}. The
robot state supplies \mbox{\(p_{\mathrm{EE}}\)},
\mbox{\(R_{\mathrm{EE}}\)}, \mbox{\(\dot p_{\mathrm{EE}}\)}, and
\mbox{\(\omega_{\mathrm{EE}}\)} for feedback.

The Cartesian pose error and the measured velocities determine the impedance
wrench \mbox{\(F=[f^\top,m^\top]^\top\)} according to
\mbox{\Cref{subsec:cartesian_pose_error,sec:cartesian_impedance_control}}.
The Jacobian transpose maps this wrench to
\mbox{\(\tau_{\mathrm{cart}}\)}. The secondary null-space torque
\mbox{\(\tau_{\mathrm{null}}\)} and model Coriolis contribution
\mbox{\(\tau_c(q,\dot q)\)} are then added before the commanded joint torque
\mbox{\(\tau_{\mathrm{cmd}}\)} is returned to libfranka.

The desired orientation \mbox{\(R_d\)} remains the reference of the impedance
law. Contact Establishment holds it constant. The measured end-effector
rotation is the closed-loop contact response to this fixed reference.

\Added{The end-effector pose supplied by the robot state provides
\mbox{\(p_{\mathrm{EE}}\)} and \mbox{\(R_{\mathrm{EE}}\)} directly.}

The implementation can apply a rotational mask by resolving
\mbox{\(e_R\)} in the surface frame, retaining the enabled components, and
transforming the result back to the base frame. The mask acts on the rotational
spring error, while the damping term continues to use the measured angular
velocity. The controller contains two impedance branches,
one decoupled and one shifted to a virtual \abbr{CoC}, and the active state
selects between them.

The complete impedance-controlled command follows
\mbox{\Cref{eq:nullspace_complete_torque_command}}.

Here \mbox{\(\tau_{\mathrm{null}}\)} is the secondary null-space torque of
\mbox{\Cref{subsec:complete_nullspace_torque}} and
\mbox{\(\tau_c(q,\dot q)\)} is the Coriolis and centrifugal contribution
obtained from the libfranka model. The \mbox{\abbr{FCI}} supplies gravity
compensation for the external joint-torque command, as described in
\mbox{\Cref{subsec:coriolis_gravity_compensation}}. The null-space pose-hold
experiment of \mbox{\Cref{sec:nullspace_hold_study}} adds an
experiment-specific disturbance torque.

The implemented controller is used in two configurations in this thesis. The
surface-contact configuration generates a state-dependent Cartesian reference
for tool orientation, surface approach, contact establishment and the
subsequent grinding state. The Cartesian pose-hold configuration is used for
the separate null-space investigation of \mbox{\Cref{sec:nullspace_hold_study}}.
Both execute the callback above and differ in the generated reference and active
impedance.


\section{Surface-Contact Sequence}
\label{sec:implemented_configurations}
\label{subsec:implementation_contact_sequence}
\label{sec:control_phases}

A surface-contact experiment passes through the controller states drawn in
\mbox{\Cref{fig:phase_flow_chart}}. The robot may first move to the stored
initial joint configuration \mbox{\(q_{\mathrm{init}}\)}. Alternatively,
operator input \texttt{g} enters Manual Guidance, and input \texttt{s} starts
the sequence from the current guided configuration \mbox{\(q\)}. Input
\texttt{q} stores that configuration as \mbox{\(q_{\mathrm{init}}\)} for a
later session. During active control, input \texttt{g} enters Manual Guidance.
Input \texttt{p} then captures the reached pose and restarts the originating
controller configuration. A surface-contact sequence restarts at Tool
Orientation. In either Cartesian hold configuration, the reached pose becomes
the new held reference. Tool Orientation advances to Surface
Approach after its minimum duration and either satisfaction of the configured
orientation criteria or the orientation timeout. Surface Approach advances to
Pre-Contact Hold when the tool clearance reaches its threshold. Reaching the
maximum approach distance before that threshold terminates the experiment. The optional holds
remain on the main path in the chart. A disabled hold advances
immediately, while operator confirmation releases an enabled hold. Contact
Establishment advances after the moment-change criterion and minimum duration,
    or through its independent timeout. Pre-Grinding Hold then precedes Grinding.
    Operator
input \texttt{t} from the contact sequence enters Contact-Impedance Hold. The
hold retains the current Cartesian pose while \mbox{\(K_p\)},
\mbox{\(K_R\)}, or \mbox{\(r_c\)} is set for the next sequence. Operator
input \texttt{s} restarts that sequence at Tool Orientation.

\subsection{Surface and Tool Reference}
\label{subsec:implemented_surface_task_frame}
\label{sec:tool_orientation_given_surface}
\label{sec:surface_task_plane}

The controller constructs the surface frame according to
\mbox{\Cref{subsec:surface_task_frame}} from a configured surface point
\mbox{\(p_s\)}, the surface orientation, and a configured first-tangent hint.
That configured parameter supplies the in-plane reference direction of
\mbox{\Cref{subsec:surface_task_frame}}. When it lies close to
\mbox{\(n_s\)}, the controller applies a fallback direction. The resulting
directions \mbox{\(t_1\)}, \mbox{\(t_2\)} and \mbox{\(n_s\)} define the descent
direction \mbox{\(-n_s\)} and the surface-relative orientation command. They
also resolve the directional Cartesian stiffness and damping, a surface-fixed
compliance-centre displacement, and the experimental quantities.

The tool normal is calibrated once in the end-effector frame. Its current
direction in the base frame follows from the measured end-effector
orientation:

\begin{equation}
n_{\mathrm{Tool},0}=R_{\mathrm{EE}}n_{\mathrm{Tool,EE}}.
\label{eq:implementation_current_tool_normal}
\end{equation}

The configured orientation offset about the two surface tangents is represented
by the rotation vector

\begin{equation}
\theta_{\mathrm{offset}}
=
\theta_{\mathrm{offset},t_1}t_1
+
\theta_{\mathrm{offset},t_2}t_2
\in\mathbb{R}^3.
\label{eq:implementation_tilt_rotation_vector}
\end{equation}

Its magnitude \mbox{\(\lVert\theta_{\mathrm{offset}}\rVert\)} specifies the
pre-contact orientation offset relative to the configured surface reference.
Tool Orientation applies this offset. Contact Establishment then holds the
captured orientation reference while contact produces the measured response.
For a non-zero offset, the corresponding unit
rotation axis is

\begin{equation}
u_{\mathrm{offset}}
=
\frac{\theta_{\mathrm{offset}}}{\lVert\theta_{\mathrm{offset}}\rVert},
\label{eq:implementation_offset_rotation_axis}
\end{equation}

and the axis--angle relation of \mbox{\Cref{eq:rodrigues_formula}} gives the
offset rotation matrix

\[
R_{\mathrm{offset}}
=
R\!\left(u_{\mathrm{offset}},\lVert\theta_{\mathrm{offset}}\rVert\right).
\]

This matrix is the identity for a zero configured offset. The vector permits offsets
about either surface tangent and along intermediate tangent-plane directions.

Since \mbox{\(n_s\)} points out of the surface, the tool-normal direction for
a tool face parallel to the surface is \mbox{\(-n_s\)}. Applying the
configured orientation offset to that direction gives the desired tool-normal
direction

\begin{equation}
n_d
=
R_{\mathrm{offset}}\left(-n_s\right).
\label{eq:implementation_tool_normal_target}
\end{equation}

For \mbox{\(\theta_{\mathrm{offset}}=0\)},
\mbox{\(R_{\mathrm{offset}}=I\)} and \mbox{\(n_d=-n_s\)}. The shortest rotation that aligns the captured tool
direction with \mbox{\(n_d\)} is applied to the complete start orientation.
The implementation can additionally prescribe a twist about the desired tool
axis to fix the rectangular face's in-plane orientation. A centred rectangle
is unchanged by a half-turn, so the equivalent orientation closest to the
captured start pose is selected. The settings used for the
measurements are stated in \mbox{\Cref{ch:methodology}}.


\label{sec:tool_contact_geometry}%
Surface approach uses all four tool-face corners because an inclined face
approaches the plane first at a corner or along an edge. The tool face is
represented as a rectangle fixed in the end-effector frame.
Its centre offset, half-width vector, and half-length vector define the four
end-effector-frame corner offsets \mbox{\(r_{i,\mathrm{EE}}\)},

\begin{equation}
r_{i,\mathrm{EE}}\in
\left\{
r_{\mathrm{face,EE}}
\mathbin{\pm}r_{\mathrm{width,EE}}
\mathbin{\pm}r_{\mathrm{length,EE}}
\right\}.
\label{eq:implementation_tool_face_vertices}
\end{equation}

The offsets are defined from the tool centre point, which coincides with the
end-effector origin in this implementation,
\mbox{\(p_{\mathrm{TCP}}=p_{\mathrm{EE}}\)}. During surface approach the four
corners determine the minimum tool clearance and the geometric tool reference
used for contact establishment, as described in
\mbox{\Cref{subsec:implementation_clearance_detection}}.

\subsection{Tool Orientation}
\label{subsec:implementation_tool_orientation_phase}

\Added{The Tool Orientation state constructs the desired tool direction relative
to the configured normal \mbox{\(n_s\)}. With
\mbox{\(\theta_{\mathrm{offset}}=0\)}, the target tool face is parallel to the
configured plane. A non-zero configured orientation offset moves the tool
towards the corresponding surface-relative orientation before Surface Approach.
The captured start position is held while the desired orientation advances
towards the target of
\mbox{\Cref{eq:implementation_tool_normal_target}} through a rate-limited
interpolation. The transition uses the tool-axis error
\mbox{\(\theta_{\mathrm{app,err}}\)}, the angle between the current and the
target tool axis. When the twist is commanded, the transition also uses the
remaining spin error about that axis. Each is compared with its own configured
tolerance, \mbox{\(\varepsilon_{\mathrm{app}}\)} for
\mbox{\(\theta_{\mathrm{app,err}}\)}. A minimum duration prevents immediate
acceptance of a transient orientation, while the state timeout
\mbox{\(t_{\mathrm{end}}\)} supplies the alternative transition. The end-effector orientation reached at this
transition is retained throughout Surface Approach.}

\subsection{Surface Approach, Clearance and Tool-Point Selection}
\label{subsec:implementation_surface_approach_phase}
\label{subsec:implementation_clearance_detection}

Surface approach advances the TCP towards the plane along
\mbox{\(-n_s\)}. Its scalar coordinate \mbox{\(s_{\mathrm{app}}(t)\)} is
the commanded travel from the TCP position \mbox{\(p_{\mathrm{TCP,start}}\)}
captured when the state begins at \mbox{\(t_{\mathrm{app},0}\)},

\begin{equation}
s_{\mathrm{app}}(t)
=
\begin{cases}
v_{\mathrm{app}}\left(t-t_{\mathrm{app},0}\right),
& t_{\mathrm{app},0}\leq t<t_{\mathrm{app,max}},\\[4pt]
s_{\mathrm{app,max}}, & t\geq t_{\mathrm{app,max}},
\end{cases}
\label{eq:implementation_approach_coordinate}
\end{equation}

with the configured descent speed \mbox{\(v_{\mathrm{app}}\)}, the
configured maximum descent distance \mbox{\(s_{\mathrm{app,max}}\)}, and
\mbox{\(t_{\mathrm{app,max}}\)} the instant at which the ramp reaches that
distance. Both configured values are listed in
Table~\ref{tab:experimental_phase_parameters}, and the saturation fixes the
largest commanded approach displacement. The desired TCP
position follows as

\begin{equation}
p_d(t)=p_{\mathrm{TCP,start}}-s_{\mathrm{app}}(t)n_s,
\label{eq:implementation_approach_reference}
\end{equation}

During the linear approach, the desired TCP velocity is
\mbox{\(\dot p_d(t)=-v_{\mathrm{app}}n_s\)}. Reaching
\mbox{\(s_{\mathrm{app,max}}\)} before the clearance criterion is satisfied
terminates the approach. For an inclined tool face, the corner closest to the
plane can lie well below the TCP. The controller evaluates the four corners of
\mbox{\Cref{fig:face_feature_selection}} in every control cycle. Their
positions and clearances determine the geometric tool reference used to
construct the contact-establishment trajectory.

The base-frame position \mbox{\(p_i(t)\)} of tool-face corner \mbox{\(i\)} is

\begin{equation}
p_i(t)
=
p_{\mathrm{TCP}}(t)+R_{\mathrm{EE}}(t)r_{i,\mathrm{EE}}.
\label{eq:implementation_corner_position}
\end{equation}

Its surface-normal clearance \mbox{\(h_i(t)\)} from the configured surface reference is

\begin{equation}
h_i(t)
=
n_s^\top\left(p_i(t)-p_s\right).
\label{eq:implementation_corner_clearance}
\end{equation}

Smaller values of \mbox{\(h_i\)} place a corner closer to the surface. Since
\mbox{\(p_{\mathrm{TCP}}\)} and \mbox{\(p_s\)} are common to all four
corners, comparing the clearances \mbox{\(h_i\)} is equivalent to comparing
the rotated corner offsets along the surface approach direction. The
implementation uses this equivalent form for the corner comparison.

The minimum tool clearance \mbox{\(h_{\mathrm{Tool}}(t)\)} is the minimum of
the four surface-normal corner clearances:

\begin{equation}
h_{\mathrm{Tool}}(t)
=
\min_{i\in\{1,2,3,4\}}h_i(t).
\label{eq:implementation_tool_clearance}
\end{equation}

The state ends at the clearance transition, where

\begin{equation}
h_{\mathrm{Tool}}(t)\leq h_{\mathrm{clearance}},
\label{eq:implementation_clearance_transition}
\end{equation}

with \mbox{\(h_{\mathrm{clearance}}\)} the configured tool clearance of
Table~\ref{tab:experimental_phase_parameters}. The approach trajectory is
generated for the TCP, whereas the transition to Contact Establishment is determined from the
physical tool geometry. Since \mbox{\(h_{\mathrm{Tool}}\)} is the minimum
clearance of the four tool-face corners,
\mbox{\(h_{\mathrm{clearance}}\)} specifies the clearance of the rectangular
tool-face corner closest to the plane. For the experimental value
\mbox{\(h_{\mathrm{clearance}}=0.020\,\mathrm{m}\)}, this part of the
tool face is \mbox{\(20\,\mathrm{mm}\)} above the configured reference plane at the
transition. This geometric criterion provides the same specified tool clearance
for different tool orientations and is purely geometric.

At the clearance transition, the same four clearances determine the selected
tool point used for contact establishment. A corner belongs to the selected index set
\mbox{\(\mathcal I_{\mathrm{sel}}\)} when its clearance lies within the
tool-point selection tolerance
\mbox{\(\varepsilon_{\mathrm{sel}}\)}:

\begin{equation}
\mathcal I_{\mathrm{sel}}
=
\left\{
i\in\{1,2,3,4\}
\;\middle|\;
h_i-h_{\mathrm{Tool}}\leq\varepsilon_{\mathrm{sel}}
\right\}.
\label{eq:implementation_selected_corner_set}
\end{equation}

The tolerance is recorded in \mbox{\Cref{tab:calibrated_tool_geometry}}. The
principal geometric cases contain one selected corner, two neighbouring
selected corners, or all four corners. These give the leading corner, the
leading-edge midpoint, and the tool-face centre, respectively. With
\mbox{\(N=\lvert\mathcal I_{\mathrm{sel}}\rvert\)}, the selected tool-point
offset \mbox{\(r_{\mathrm{Tool,EE}}\)} is the mean of the selected corner
offsets,

\begin{equation}
r_{\mathrm{Tool,EE}}
=
\frac{1}{N}\sum_{i\in\mathcal I_{\mathrm{sel}}}r_{i,\mathrm{EE}}.
\label{eq:implementation_leading_feature_average}
\end{equation}

The selected tool point \mbox{\(p_{\mathrm{Tool}}\)} is the geometric reference
selected from the calibrated tool face to construct the contact-establishment
trajectory. Its position is

\begin{equation}
p_{\mathrm{Tool}}=p_{\mathrm{TCP}}+R_{\mathrm{EE}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_contact_point_position}
\end{equation}

\mbox{\Cref{fig:leading_feature_cases}} gives the selected corner in panel~(a),
edge midpoint in panel~(b), and tool-face centre in panel~(c). For the tool-face centre,
\mbox{\(r_{\mathrm{Tool,EE}}=r_{\mathrm{face,EE}}\)}. That calibrated offset
lies along the end-effector \mbox{\(z\)}-axis, so the selected tool point then
sits on that axis directly beneath the TCP.

\begin{figure}[H]
  \centering
  \input{figures/leading_feature_cases.tex}
  \caption[Principal selected tool points for the rectangular tool face.]{%
    \Added{Principal selected tool points: (a) corner, (b) edge midpoint, and
    (c) tool-face centre.}}
  \label{fig:leading_feature_cases}
\end{figure}

The minimum clearance \mbox{\(h_{\mathrm{Tool}}\)} determines when approach
ends. The offset \mbox{\(r_{\mathrm{Tool,EE}}\)} determines which geometric
tool point the contact-establishment reference uses. At the clearance
transition the selected offset is retained in end-effector coordinates and
then held constant throughout contact establishment.

Three points remain distinct in this construction. The impedance law regulates
the Cartesian reference point \mbox{\(p_{\mathrm{TCP}}\)}. The selected tool
point \mbox{\(p_{\mathrm{Tool}}\)} belongs to the physical tool geometry, and
its base-frame offset
\mbox{\(r_{\mathrm{Tool}}=R_{\mathrm{EE}}r_{\mathrm{Tool,EE}}=p_{\mathrm{Tool}}-p_{\mathrm{TCP}}\)}
changes with the tool orientation. The virtual \abbr{CoC} \mbox{\(p_c\)} of
\mbox{\Cref{sec:centre_of_compliance}} is a software-defined impedance
reference and is independent of the tool geometry.

\subsection{Operator-Controlled Hold Before Contact Establishment}
\label{subsec:implementation_pre_contact_hold}

The optional hold state before contact establishment maintains the captured pose
until continuation is confirmed. The contact-establishment references are then captured from
the current measured state.

\subsection{Contact Establishment}
\label{subsec:implementation_setup_phase}
\label{sec:surface_frame_gains}
\label{subsec:phase_dependent_gain_construction}

In the surface-contact experiments, contact establishment begins directly at the clearance
transition. Its Cartesian reference is constructed from the selected tool
point and end-effector pose captured at that instant. The captured orientation
\mbox{\(R_{\mathrm{EE,clearance}}\)} and TCP position
\mbox{\(p_{\mathrm{TCP,clearance}}\)} are taken at the clearance-transition
instant \mbox{\(t_{\mathrm{CE,start}}\)},

\begin{equation}
R_{\mathrm{EE,clearance}}=R_{\mathrm{EE}}(t_{\mathrm{CE,start}}),
\qquad
p_{\mathrm{TCP,clearance}}=p_{\mathrm{TCP}}(t_{\mathrm{CE,start}}).
\label{eq:implementation_clearance_pose}
\end{equation}

The corresponding selected tool-point position
\mbox{\(p_{\mathrm{Tool,clearance}}\)} is

\begin{equation}
p_{\mathrm{Tool,clearance}}
=p_{\mathrm{TCP,clearance}}+R_{\mathrm{EE,clearance}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_clearance_tool_point}
\end{equation}

Its orthogonal projection onto the configured surface reference defines the
surface reference point \mbox{\(p_{\mathrm{Tool},0}\)},

\begin{equation}
p_{\mathrm{Tool},0}
=p_{\mathrm{Tool,clearance}}
-n_sn_s^\top\left(p_{\mathrm{Tool,clearance}}-p_s\right).
\label{eq:implementation_projected_tool_point}
\end{equation}

\mbox{\(p_{\mathrm{Tool},0}\)} is the point on the configured
reference plane directly below the selected tool point at the clearance
transition.

Contact establishment generates the press evaluated in the experiments. The scalar
coordinate \mbox{\(s_{\mathrm{CE}}(t)\)} gives the selected tool point's
commanded displacement from \mbox{\(p_{\mathrm{Tool},0}\)} towards the surface.
Its initial value is the negative of that point's surface-normal coordinate,

\begin{equation}
s_{\mathrm{CE}}(t_{\mathrm{CE,start}})
=
-n_s^\top\left(p_{\mathrm{Tool,clearance}}-p_s\right).
\label{eq:implementation_setup_initial_coordinate}
\end{equation}

The selected point remains above the configured reference plane at the transition, so
\mbox{\(s_{\mathrm{CE}}(t_{\mathrm{CE,start}})<0\)}. This initial value makes
the first contact-establishment reference equal to \mbox{\(p_{\mathrm{Tool,clearance}}\)} and avoids
a position step.

The coordinate advances at the configured press speed
\mbox{\(v_{\mathrm{CE}}\)} from \mbox{\(t_{\mathrm{CE,start}}\)} until it reaches
the configured endpoint \mbox{\(s_{\mathrm{CE,max}}\)} at
\mbox{\(t_{\mathrm{CE,max}}\)}, then remains constant:

\begin{equation}
s_{\mathrm{CE}}(t)
=
\begin{cases}
s_{\mathrm{CE}}(t_{\mathrm{CE,start}})
+v_{\mathrm{CE}}\left(t-t_{\mathrm{CE,start}}\right),
& t_{\mathrm{CE,start}}\leq t<t_{\mathrm{CE,max}},\\[4pt]
s_{\mathrm{CE,max}}, & t\geq t_{\mathrm{CE,max}}.
\end{cases}
\label{eq:implementation_setup_press_coordinate}
\end{equation}

The desired selected-tool-point position \mbox{\(p_{\mathrm{Tool},d}(t)\)} is

\begin{equation}
p_{\mathrm{Tool},d}(t)
=
p_{\mathrm{Tool},0}-s_{\mathrm{CE}}(t)n_s.
\label{eq:implementation_setup_face_point_reference}
\end{equation}

\mbox{\Cref{app:controller_parameters}} records the configured press speed and
endpoint.

Throughout contact establishment the desired orientation is

\begin{equation}
R_d(t)=R_{\mathrm{EE,clearance}}.
\label{eq:implementation_setup_orientation_reference}
\end{equation}

The contact-establishment trajectory is defined for the selected geometric
tool point, whereas the Cartesian impedance law regulates the TCP. The desired
tool-point position is converted to the corresponding TCP reference. At the
retained orientation, their rigid-body relation is

\begin{equation}
p_{\mathrm{Tool},d}(t)
=
p_d(t)+R_{\mathrm{EE,clearance}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_setup_rigid_body_relation}
\end{equation}

Solving this relation gives the desired TCP position \mbox{\(p_d(t)\)} as

\begin{equation}
p_d(t)
=
p_{\mathrm{Tool},d}(t)-R_{\mathrm{EE,clearance}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_setup_tcp_reference}
\end{equation}

During the linear part of the ramp, the desired TCP velocity is
\mbox{\(\dot p_d=-v_{\mathrm{CE}}n_s\)}. It is zero after
\mbox{\(s_{\mathrm{CE,max}}\)} is reached. The controller generates the press
by prescribing the selected tool-point trajectory and reconstructing the TCP
target that realises it. Because the surface restricts this commanded motion,
the resulting Cartesian position error generates the press. The configured
endpoint lies below the configured reference plane and defines the Cartesian
spring reference.

\mbox{\Cref{fig:setup_reference}} shows the complete construction from the
projected tool point to the TCP target.

\begin{figure}[H]
  \centering
  \input{figures/setup_reference.tex}
  \caption{Contact-establishment reference generation.}
  \label{fig:setup_reference}
\end{figure}

Contact Establishment holds the orientation reference constant. Its finite
rotational stiffness permits contact-induced end-effector rotation. When the virtual \abbr{CoC} is enabled,
the point-shifted matrices of
\mbox{\Cref{sec:centre_of_compliance}} additionally couple the
translational press to the commanded moment; the same contact-establishment position
reference is used in both cases.

The impedance acting on that reference changes at the same transition, from
the approach set to the contact-establishment set. Directional stiffness,
directional damping, and the selected impedance reference point determine the
active law. That point is either the TCP or a shifted virtual \abbr{CoC}. The
controller constructs the directional stiffness and damping first and applies
the compliance-centre transformation afterwards.

Directional Cartesian stiffness and damping are defined relative to the
surface frame and transformed to the robot base frame by the congruence of
\mbox{\Cref{sec:stiffness_damping_representation}}. Each state of the sequence
activates its own stiffness and damping set in the configured surface frame, and the contact-establishment
translational frame remains configurable. Contact Establishment and Grinding draw on the same
source stiffness and damping blocks; the state transition changes the generated
Cartesian reference and the choice between the coupled and decoupled branch.
An operator-controlled hold can temporarily apply dedicated hold stiffness and
damping while maintaining the current reference. The numerical values used in
the experiments are given in \mbox{\Cref{ch:methodology}}.

For the states using inertia-scaled damping, the directional coefficients are
calculated from \mbox{\Cref{eq:inertia_scaled_damping}}. The implementation
obtains the joint-space inertia \mbox{\(M(q)\)} and Jacobian \mbox{\(J(q)\)}
from the libfranka model. An \mbox{\abbr{LDLT}} factorisation solves the
required system while leaving \mbox{\(M(q)^{-1}\)} implicit. The result is
cached for each stiffness-and-damping configuration and recalculated when that
configuration is activated.
Coefficient bounds, validity checks, and the fallback damping matrix are
recorded in \mbox{\Cref{app:controller_parameters}}.

The surface-contact experiments used inertia-scaled damping during
Surface Approach and Contact Establishment.

\label{sec:self_alignment_virtual_center}

The point-shift formulation derived in
\mbox{\Cref{sec:centre_of_compliance}} is implemented with the displacement
\mbox{\(r_{c,0}=p_c-p_{\mathrm{TCP}}\)}. Two definitions are supported,
because the meaning of a fixed displacement depends on the frame that holds
it.

A tool-fixed displacement is configured in end-effector coordinates. Its
base-frame vector \mbox{\(r_{c,0}=R_{\mathrm{EE}}r_{c,\mathrm{EE}}\)} is
updated from the measured end-effector orientation in every callback
and rotates as the end effector rotates. By contrast, a surface-fixed
displacement is configured in surface coordinates, so
\mbox{\(r_{c,0}=R_{\mathrm{surface}}r_{c,S}\)} stays constant during contact establishment,
the surface frame being fixed for one controller session. The configuration
loader requires exactly one of the two definitions to be active when the
virtual centre is enabled. This validation enforces exclusive selection between
the two definitions. All non-zero experimental displacements used the tool-fixed
definition in end-effector coordinates.

The source translational and rotational matrices are assembled into
block-diagonal spatial stiffness and damping at \mbox{\(p_c\)}. The stiffness
and damping are shifted according to
\mbox{\Cref{eq:coupled_tcp_stiffness,eq:coupled_tcp_damping}}.

For a tool-fixed displacement the shifted base-frame matrices are updated
whenever the measured end-effector orientation changes, whereas a
surface-fixed displacement leaves them constant while the source matrices
remain constant. Setting \mbox{\(r_{c,0}=0\)} makes the adjoint the identity and
returns the decoupled block-diagonal form.

During contact establishment this point-shifted impedance allows the commanded normal press
to contribute to the rotational response. The influence of the
compliance-centre position on that response is evaluated experimentally in
\mbox{\Cref{ch:results_discussion}}. Controller states configured for a virtual
\abbr{CoC} activate the coupled branch; the experimental cases
are specified in \mbox{\Cref{ch:methodology}} and
\mbox{\Cref{app:controller_parameters}}.

The model-estimated external wrench supplied by libfranka is stored at the
clearance transition for the optional termination condition. After the
configured minimum duration, contact establishment can terminate when the
estimated external moment change exceeds the configured threshold, or through
the independent timeout. Every contact experiment followed this timeout
transition.

\section{Cartesian Pose Hold}
\label{subsec:implementation_pose_hold}
\label{sec:nullspace_conditioning_implementation}

Cartesian pose hold starts after the robot moves to the stored initial joint
configuration \mbox{\(q_{\mathrm{init}}\)}, or directly from the current
guided configuration \mbox{\(q\)} when the operator types \texttt{h} in
Manual Guidance. The current end-effector pose is then captured at the entry instant
\mbox{\(t_0\)} and used to define the fixed references
\mbox{\(p_d=p_{\mathrm{EE}}(t_0)\)} and
\mbox{\(R_d=R_{\mathrm{EE}}(t_0)\)}. Its dedicated hold impedance is expressed
in the base frame. Cartesian pose hold captures these references directly at
state entry.

Modes 0--3 select zero null-space torque, projected damping, singular-value
conditioning, or both terms. The parameter \mbox{\(d_{\mathrm{null}}\)} is
adjustable in modes 1 and 3, and \mbox{\(k_\sigma\)} in modes 2 and 3. Entering
another number switches modes while the Cartesian reference and impedance
remain unchanged.

Contact-Impedance Hold, by contrast, is a controller state outside these four
null-space modes.

\Added{The four pose-hold settings were mode 0, mode 1, and mode 2 at
two values of \mbox{\(k_\sigma\)}. The surface-contact sequence used mode 3.
The disturbance and evaluated quantities are defined in
\mbox{\Cref{sec:nullspace_hold_study}}.}

The implementation specifies two numerical choices beyond
\mbox{\Cref{sec:nullspace_svd}}. The pseudoinverse threshold is the configured
relative tolerance multiplied by the largest current singular value. The
resulting joint-torque projector is symmetrised numerically, and the same matrix
produces the recorded projected joint velocity
\mbox{\(\dot q_{\mathrm{null}}\)}. For singular-value conditioning, the
controller evaluates the Jacobian at
\mbox{\(q\pm\alpha_{\mathrm{probe}}v_7\)} and compares the smallest singular
value at each probe. This comparison uses the current robot transformations.
The configured deadband sets the conditioning torque to zero. The
surface-contact sequence holds one combined setting throughout each
comparison.


\section{Robot-Side Safety and Command Handling}
\label{sec:collision_behavior_safety}
\label{subsec:robot_collision_configuration}
\label{subsec:initial_joint_posture}
\label{subsec:controller_exception_handling}

The complete joint-torque command of
\mbox{\Cref{eq:nullspace_complete_torque_command}} is returned directly to
libfranka. The configured collision and reflex monitoring supplies the
independent protection layer during the experiments. Its joint-torque and Cartesian-wrench
thresholds are recorded in
\mbox{\Cref{subsec:reproducibility_record}}. A robot communication,
motion-generation or torque-control error leaves the callback through
\mbox{\texttt{franka::Exception}} and ends the control session.

Before torque control starts, the connection is established and error recovery
is requested. The collision settings and controller configuration are
validated, the gripper action is completed, and the logging buffer is
allocated. A libfranka joint-motion generator then brings the robot to the
configured initial posture. Alternatively, the experiment starts from a pose
captured after Manual Guidance. The posture used in the experiments is recorded
in \mbox{\Cref{app:controller_parameters}}. Operator input and file writing are
handled outside the real-time thread. The joint-torque callback uses
prepared in-memory state throughout each cycle.


\section{Real-Time Data Recording}
\label{sec:recorded_signals}
\label{subsec:chronological_log_output}
\label{subsec:setup_run_evaluation}

Experimental signals are stored during torque control in a preallocated,
fixed-capacity in-memory ring buffer. Each sampled row carries the measured state, the active
reference, the calculated error and wrench, the controller state, the
secondary-controller configuration, and the returned joint torque. When the allocated
capacity is reached, the write index wraps and new rows replace the oldest.
After the callback ends, the current buffer contents are written to the \mbox{\abbr{CSV}} file in chronological
order.
