\label{ch:implementation}

settled. No further editing is to be applied to it, and any remaining concern
is raised as a comment rather than as a change.}

\Comment{In the settled prose, use ``commanded tool orientation offset'' for

inclination or a calibrated surface angle.}

\Revised{This chapter describes the real-time implementation of the Cartesian
impedance controller developed in \mbox{\Cref{ch:theory}}. The controller is written
in C++ using libfranka and Eigen and is executed through the Franka Control
Interface (\mbox{\abbr{FCI}}) with a nominal control period of
\mbox{\(1\,\mathrm{ms}\)}.}

\Revised{The software combines the Cartesian impedance law, the SVD-based null-space
controller, the configured surface and tool geometry, phase-dependent
stiffness and damping, and the virtual centre of compliance \mbox{\(p_c\)}. These components
are coordinated by a phase state machine that orients the tool, approaches the
surface, applies the set-up preload, and executes the grinding motion.
Additional operating modes provide Cartesian pose holding, set-up-impedance
holding, and manual guidance.}

\Revised{The following sections describe the software architecture, the real-time
control loop, the implemented Cartesian torque \mbox{\(\tau_{\mathrm{cart}}\)} and
null-space torque \mbox{\(\tau_{\mathrm{null}}\)} contributions,
the geometric representation of the surface and tool, the phase-dependent
impedance parameters, and the execution of the control sequence.}

\label{sec:software_architecture}

calculations, real-time execution, operator interaction, and run evaluation.
The main program coordinates these modules and manages the execution of
successive controller sessions.}

\Revised{The parameter directory is resolved relative to the controller executable.
The complete configuration is distributed over 15 files in the
\mbox{\texttt{params/}} directory. These files contain the robot connection and
logging settings, collision thresholds, gripper parameters, initial posture,
surface and tool geometry, phase settings, Cartesian gains,
inertia-scaled-damping settings, virtual-compliance-centre parameters,
null-space parameters,
disturbance-test settings, and manual-guidance settings.}

\Revised{At program start, the parameter files are read to obtain the robot address and
initial controller configuration. The robot connection is then established,
error recovery is requested, the selected collision behaviour is
assigned, and the libfranka robot model is loaded. A separate keyboard thread
is also started to receive operator requests during the controller session.
These requests are transferred through atomic variables shared with the
control loop.}

\Revised{Before every new session, all parameter files are read again and the resulting
values are stored in a new \mbox{\texttt{ControllerConfig}} object. This permits
controller and experiment parameters to be changed between runs without
recompiling the program. The loader requires all 15 parameter files and rejects
duplicate parameter names across them.}

\Revised{The start-up interface provides four controller modes:}

\begin{itemize}
    \item \Revised{the complete tool-orientation, surface-approach, set-up, and grinding
          sequence;}
    \item \Revised{Cartesian pose holding with the dedicated hold impedance;}
    \item \Revised{Cartesian pose holding with the set-up impedance; and}
    \item \Revised{manual guidance from the current robot pose.}
\end{itemize}

\Revised{The same interface provides the robot-preparation and gripper actions required
before torque control. The robot can be moved to the configured initial joint
posture, the gripper can be opened or closed, and the tool can be collected
from or returned to its configured holder posture. When manual guidance is
selected, the subsequent sequence or hold mode begins from the pose captured
after hand-guided positioning.}

\Revised{Once the operating mode and initial state have been selected, the
phase-dependent stiffness and damping matrices are constructed from the active
configuration. These matrices, together with the robot and model interfaces,
are passed to the real-time control loop.}

\Revised{Experimental signals are stored during control in a bounded ring buffer whose
memory is allocated before the torque callback begins. After the controller
session has ended, the stored samples are arranged in chronological order,
written to the configured \mbox{\abbr{CSV}} file, and used to generate the terminal
run summary. A new session can then be started from the start-up menu with a
freshly loaded configuration.}


\section{Real-Time Control Loop}
\label{sec:real_time_control_loop}

\Revised{The function \mbox{\texttt{runControlLoop}} prepares one controller session and
executes the libfranka joint-torque callback. It receives the active controller
configuration, the robot and model interfaces, the phase-dependent impedance
gains, and the operator-input signals.}

\Revised{Before torque control begins, the current robot state is read once. The
reported end-effector transformation provides the initial TCP position
\mbox{\(p_{\mathrm{start}}\)} and orientation \mbox{\(R_{\mathrm{start}}\)}, while the
measured joint configuration provides the initial posture
\mbox{\(q_{\mathrm{start}}\)}. These values initialise the desired pose of the
selected sequence or hold mode.}

\Revised{The initial state also provides an external-wrench reference for subsequent
contact evaluation. In addition, the controller initialises the configured
surface point, the surface frame, the target tool orientation, the descent
direction, and the four tool-face corners. The initial phase, phase clocks,
operator gates, set-up references, damping cache, and recording buffer are
prepared before entering the real-time callback.}

\Revised{The controller is passed to \mbox{\texttt{robot.control}} as a joint-torque callback.
For every control cycle, the callback receives the current
\mbox{\texttt{RobotState}} and the elapsed cycle duration and returns the seven
commanded joint torques \mbox{\(\tau_{\mathrm{cmd}}\)}, as shown in
\mbox{\cref{lst:libfranka_torque_callback}}.}

\begin{lstlisting}[style=cppstyle,
  caption={Registration of the joint-torque callback through
           \texttt{libfranka}.},
  label={lst:libfranka_torque_callback}]
robot.control(
    [&](const franka::RobotState& state,
        franka::Duration period) -> franka::Torques {

      // Real-time state and torque calculations

      return franka::Torques(tau_array);
    });
\end{lstlisting}

\Revised{\mbox{\Cref{fig:controller_block_diagram}} shows the signals combined into the
commanded joint torque \mbox{\(\tau_{\mathrm{cmd}}\)} during one control cycle.}

\begin{figure}[H]
  \centering
  \resizebox{\textwidth}{!}{\input{figures/controller_block_diagram.tex}}
  \caption{Torque contributions combined in one control cycle.}
  \label{fig:controller_block_diagram}
\end{figure}

\Revised{During each callback, the elapsed controller time is updated from the period
reported by libfranka. The joint state, end-effector Jacobian \mbox{\(J(q)\)}, Cartesian
velocity \mbox{\(\dot x\)}, end-effector pose, and model-estimated external wrench are then
obtained as shown in \mbox{\cref{lst:callback_state_acquisition}}.}

% The corresponding abridged source is retained in Appendix~\ref{app:code}.

\Revised{The vectors \mbox{\texttt{q\_current}} and \mbox{\texttt{dq}} contain the measured joint
configuration and velocity. The call to
\mbox{\texttt{model.zeroJacobian}} returns the \mbox{\(6\times7\)} geometric Jacobian
\mbox{\(J(q)\)} of the
configured libfranka end-effector frame. Multiplication by the measured joint
velocity \mbox{\(\dot q\)} provides the TCP linear velocity \mbox{\texttt{pdot}} and angular velocity
\mbox{\texttt{omega}}, both expressed in the robot base frame.}

\Revised{The field \mbox{\texttt{state.O\_T\_EE}} provides the current end-effector
transformation in the base frame. Its translational and rotational blocks are
assigned to \mbox{\texttt{p\_EE}} and \mbox{\texttt{R\_EE}}, respectively. The controller
therefore uses the pose reported by libfranka rather than reconstructing it
from a separate forward-kinematic model.}

\Revised{The field \mbox{\texttt{state.O\_F\_ext\_hat\_K}} provides the model-estimated
external force \mbox{\(\hat f_{\mathrm{ext}}\)} and moment. During surface approach, the transition to set-up
is determined geometrically from the tool-face clearance. At this transition,
the current estimates are stored as the external-wrench reference. During
set-up, the resulting external-moment change is used for the moment-based exit
condition. The force and moment estimates are also included in the terminal
output, set-up evaluation, and recorded experimental data.}

\Revised{Operator requests are exchanged with the callback through atomic variables.
They support transitions between the phase sequence, Cartesian pose hold,
set-up-impedance hold, and manual guidance. The same interface receives the
gate confirmations and stop request. During the dedicated hold modes, selected
null-space and set-up-impedance parameters can also be adjusted. An accepted
set-up-impedance change rebuilds the corresponding phase gains and damping
cache.}

\Revised{The phase state machine updates the desired TCP position \mbox{\(p_d\)}, desired
linear velocity \mbox{\(\dot p_d\)}, and desired orientation \mbox{\(R_d\)}. Their values
depend on the active phase:}

\begin{itemize}
    \item \Revised{tool orientation maintains the initial TCP position while advancing
          the orientation command toward the configured target;}
    \item \Revised{surface approach moves the desired position along the descent
          direction;}
    \item \Revised{set-up advances the selected contact point into the surface;}
    \item \Revised{grinding maintains the achieved preload and can add a tangential
          trajectory; and}
    \item \Revised{pose hold regulates the captured Cartesian pose.}
\end{itemize}

\Revised{After the reference has been updated, the callback calculates the Cartesian
position error \mbox{\(e_p\)} and orientation error \mbox{\(e_R\)} using the conventions introduced in
\mbox{\Cref{subsec:cartesian_pose_error}}. The phase-dependent stiffness and damping
matrices are then selected. When a phase gate is active, the dedicated gate
holding gains replace the normal phase gains.}

\Revised{The displacement error \mbox{\(\Delta x\)} and velocity error
\mbox{\(\Delta v\)} supplied to the impedance calculation are}

\begin{equation}
\Delta x
=
\begin{bmatrix}
e_p\\
e_R
\end{bmatrix},
\qquad
\Delta v
=
\begin{bmatrix}
\dot p_d-\dot p_{\mathrm{EE}}\\
-\omega_{\mathrm{EE}}
\end{bmatrix}.
\label{eq:implementation_callback_error_vectors}
\end{equation}

\Revised{The Cartesian impedance calculation returns the commanded wrench \mbox{\(F\)}}

\begin{equation}
F
=
\begin{bmatrix}
f\\
m
\end{bmatrix}
\in\mathbb{R}^6.
\label{eq:implementation_callback_wrench}
\end{equation}

\Revised{Depending on the active mode, this wrench is obtained from either the
decoupled impedance law of \mbox{\cref{eq:cartesian_impedance_control_law}} or the
point-shifted set-up impedance described in
\mbox{\Cref{sec:self_alignment_virtual_center}}.}

\Revised{The Cartesian torque contribution \mbox{\(\tau_{\mathrm{cart}}\)} is}

\begin{equation}
\tau_{\mathrm{cart}}
=
J^\top(q)F.
\label{eq:implementation_callback_cartesian_torque}
\end{equation}

\Revised{The SVD-based null-space routine calculates the secondary torque
\mbox{\(\tau_{\mathrm{null}}\)} according to the selected null-space mode. During
the Cartesian pose-hold disturbance experiment described in
\mbox{\Cref{sec:nullspace_hold_study}}, an additional joint-torque contribution
\mbox{\(\tau_{\mathrm{dist}}\)} is applied. For all other controller operation,
the disturbance torque is set to zero, \mbox{\(\tau_{\mathrm{dist}}=0\)}.}

\Revised{The Coriolis and centrifugal torque \mbox{\(\tau_c\)} is obtained from the
libfranka model. The complete torque command \mbox{\(\tau_{\mathrm{cmd}}\)} of an
impedance-controlled cycle is therefore}

\begin{equation}
\tau_{\mathrm{cmd}}
=
\tau_{\mathrm{cart}}
+
\tau_{\mathrm{null}}
+
\tau_{\mathrm{dist}}
+
\tau_c(q,\dot q).
\label{eq:implementation_callback_torque_command}
\end{equation}

\Revised{Manual guidance follows the separate joint-torque command
\mbox{\(\tau_{\mathrm{guide}}\)}:}

\begin{equation}
\tau_{\mathrm{guide}}
=
\tau_c(q,\dot q)
-
d_{\mathrm{guide}}\dot q,
\label{eq:implementation_manual_guidance_torque}
\end{equation}

\Revised{where \mbox{\(d_{\mathrm{guide}}\)} is the configured joint-damping coefficient.
After the guided pose is captured, its position, orientation, joint
configuration, and the external-wrench reference initialise the resumed sequence or hold mode.}

\Revised{For impedance-controlled cycles, the selected state, reference, error, wrench,
phase, null-space, disturbance, and joint-torque quantities are sampled at the
configured interval and copied into a preallocated ring buffer. When the buffer
capacity is reached, the most recent samples replace the oldest entries.}

\Revised{The callback ends when the configured run duration expires, an operator stop is
requested, the maximum approach distance is reached, or libfranka terminates
the motion. After torque control has ended, the ring-buffer entries are placed
in chronological order and returned together with the final controller state.
File writing and post-run evaluation are performed outside the real-time
callback.}

\section{Implemented Cartesian Impedance Controller}
\label{sec:state_model}

\Revised{The mathematical formulation of the Cartesian impedance controller is given in
\mbox{\Cref{sec:cartesian_impedance_control}}. This section describes how the pose
errors, phase-dependent gains, and Cartesian wrench \mbox{\(F\)} are evaluated in the
software.}

\Revised{The callback first selects the desired orientation associated with the active
phase. During tool orientation, the desired orientation follows the
interpolated orientation command. Surface approach uses the final tool-target
orientation. At the transition to set-up, the current orientation is captured
and held constant throughout set-up and grinding. Cartesian pose hold uses the pose
stored for the active hold mode.}

\Revised{The position error \mbox{\(e_p\)} and orientation error \mbox{\(e_R\)} are evaluated as shown in
\mbox{\cref{lst:implementation_pose_error}}.}

% The corresponding abridged source is retained in Appendix~\ref{app:code}.

\Revised{The function \mbox{\texttt{orientationError}} forms the current-to-desired relative
rotation and converts it to an axis--angle vector. The resulting local rotation
vector is transformed to the robot base frame:}

\begin{equation}
\Delta R=R_{\mathrm{EE}}^\top R_d,
\qquad
e_R=R_{\mathrm{EE}}u\phi,
\label{eq:implementation_orientation_error_evaluation}
\end{equation}

\Revised{A rotation angle below the numerical tolerance returns a zero vector. The
orientation-error convention therefore corresponds to the corrective
base-frame error \mbox{\(e_R\)} defined in
\mbox{\Cref{subsec:cartesian_pose_error}}.}

\Revised{The rotational mask is applied after the error has been transformed to the
base frame. The function first expresses \mbox{\(e_R\)} in the surface frame, selects
the enabled components about \mbox{\(t_1\)}, \mbox{\(t_2\)}, and \mbox{\(n_s\)}, and transforms the
result back to the base frame. The active configuration enables all three
components. The mask acts on the rotational spring error, while rotational
damping continues to use the measured angular velocity and the selected
damping matrix.}

\Revised{The callback then combines the translational and rotational quantities into
the six-dimensional displacement and velocity-error vectors used by the
impedance routine. The desired angular velocity is zero in the implemented
control sequence.}


\Revised{The variables \mbox{\texttt{Kp\_used}}, \mbox{\texttt{Dp\_used}},
\mbox{\texttt{KR\_used}}, and \mbox{\texttt{DR\_used}} contain the gains selected for the
current phase. Their construction and phase assignment are described in
\mbox{\Cref{sec:surface_frame_gains}}. The implementation variable
\mbox{\texttt{wrench}} follows the force--moment order used in Chapter~2, while
\mbox{\texttt{tau\_task}} corresponds to the Cartesian impedance torque
\mbox{\(\tau_{\mathrm{cart}}\)}.}

\Revised{The function \mbox{\texttt{computeCartesianImpedanceWrench}} selects between the
decoupled Cartesian impedance and the point-shifted impedance associated with
the virtual centre of compliance \mbox{\(p_c\)}. The decoupled branch is implemented by
applying the translational and rotational gain blocks separately:}

\begin{equation}
F
=
\begin{bmatrix}
K_p e_p+D_p(\dot p_d-\dot p_{\mathrm{EE}})\\
K_R e_R-D_R\omega_{\mathrm{EE}}
\end{bmatrix}.
\label{eq:implementation_decoupled_wrench}
\end{equation}

\Revised{This branch is used during tool orientation, surface approach, grinding, and
the standard Cartesian pose hold. It is also used during set-up when the
virtual centre of compliance \mbox{\(p_c\)} is disabled.}

\Revised{The coupled branch is selected when the virtual centre of compliance
\mbox{\(p_c\)} is
enabled during set-up or during the dedicated set-up-impedance hold mode:}

\begin{center}
\begin{tabular}{ll}
\textbf{Coupled} & \(p_c\) enabled in set-up or set-up-impedance hold \\
\textbf{Decoupled} & All other phases and modes
\end{tabular}
\end{center}

\Revised{In this branch, the translational and rotational gain blocks are assembled into
spatial \mbox{\(6\times6\)} matrices and shifted from the configured centre of
compliance \mbox{\(p_c\)} to the TCP. The construction of these matrices and the two
implemented definitions of the compliance-centre lever \mbox{\(r_c\)} are described in
\mbox{\Cref{sec:self_alignment_virtual_center}}.}

\Revised{The wrench \mbox{\(F\)} returned by either branch is mapped to joint torque
\mbox{\(\tau_{\mathrm{cart}}\)} by
\mbox{\texttt{J.transpose()}}\allowbreak
\mbox{\texttt{* wrench}}. The resulting
\mbox{\texttt{tau\_task}} contribution is subsequently combined with the null-space,
disturbance, and Coriolis torque contributions in the real-time callback.}

\section{SVD-Based Null-Space Control}
\label{sec:nullspace_conditioning_implementation}

\Revised{The mathematical formulation of the null-space projector, projected damping,
and singular-value conditioning torque is presented in
\mbox{\Cref{sec:nullspace_svd}}. This section describes their implementation in the
function \mbox{\texttt{computeNullspaceTorque}}, which is evaluated during every
impedance-controlled callback.}

\Revised{The function receives the current geometric Jacobian \mbox{\(J(q)\)}, measured
joint velocity \mbox{\(\dot q\)},
robot state, model interface, and active null-space parameters. The current
joint configuration is mapped from the robot state, and the full singular value
decomposition of the \mbox{\(6\times7\)} Jacobian \mbox{\(J(q)\)} is calculated. The
pseudoinverse \mbox{\(J^+\)} and joint-torque null-space projector \mbox{\(N_\tau\)} are
then constructed as shown in
\mbox{\cref{lst:implementation_nullspace_projector}}.}

% The corresponding abridged source is retained in Appendix~\ref{app:code}.

\Revised{The relative tolerance
\mbox{\texttt{nullspace\_svd\_relative\_tolerance}} is multiplied by the largest
singular value of the current Jacobian \mbox{\(J(q)\)}. This produces the singular-value
threshold used during the current callback. Each singular direction above this
threshold contributes to the pseudoinverse with the reciprocal
\mbox{\(1/\sigma_i\)}. The remaining reciprocal entries are set to zero.}

\Revised{The implementation forms the joint-torque projector directly according to the
expression derived in \mbox{\Cref{subsec:nullspace_projectors}}. Averaging the
projector with its transpose removes small numerical asymmetries caused by
floating-point calculations.}

\Revised{The measured joint velocity \mbox{\(\dot q\)} is subsequently projected into the numerical
null space. The active \mbox{\texttt{NullspaceMode}} determines which secondary
torque contributions are evaluated:}

\begin{equation}
\dot q_{\mathrm{null}}=N_\tau\dot q,
\qquad
\tau_d=-d_{\mathrm{null}}\dot q_{\mathrm{null}}.
\label{eq:implementation_projected_nullspace_damping}
\end{equation}

\Revised{The four selectable modes are defined in the controller as}

\begin{table}[H]
\centering
\caption{Selectable null-space torque contributions.}
\label{tab:implementation_nullspace_modes}
\begin{tabular}{ll}
\hline
\textbf{Mode} & \textbf{Returned secondary torque} \\
\hline
Disabled & \(0\) \\
Damping only & \(\tau_d\) \\
Sigma only & \(\tau_\sigma\) \\
Combined & \(\tau_d+\tau_\sigma\) \\
\hline
\end{tabular}
\end{table}

\Revised{The disabled mode returns zero secondary torque. The damping-only mode returns
the negative projected joint-velocity damping. The sigma-only mode evaluates
the singular-value conditioning contribution, while the combined mode adds
both contributions.}

\Revised{For singular-value conditioning, the seventh column of the current
right-singular-vector matrix is selected and normalised. This vector
corresponds to the redundant direction \mbox{\(v_7\)} introduced in
\mbox{\Cref{subsec:svd_nullspace_characterisation}}. Two nearby joint
configurations are then formed along its positive and negative directions.}


\Revised{The parameter \mbox{\texttt{nullspace\_probe\_step\_rad}} defines the
joint-space distance \mbox{\(\alpha_{\mathrm{probe}}\)} between the current
configuration and the two sampled configurations. The Jacobians are evaluated
using the current flange-to-end-effector and end-effector-to-stiffness-frame
transformations provided in the robot state.}

\Revised{The smallest singular values \mbox{\(\sigma_{\min}(q_\pm)\)} of the sampled Jacobians are compared through
the configured deadband. The sign of their difference selects the sampled
direction with the larger value of \mbox{\(\sigma_{\min}\)}.}


\Revised{The parameter \mbox{\texttt{nullspace\_sigma\_deadband}} specifies the minimum
difference required for selecting one sampled direction. Within the deadband,
the sigma-only mode returns zero torque and the combined mode preserves the
damping contribution.}

\Revised{The vector \mbox{\texttt{best\_direction}} corresponds to \mbox{\(sv_7\)}. Multiplication
by the projector preserves its numerical null-space component, while
\mbox{\texttt{nullspace\_sigma\_gain}} specifies the conditioning-torque magnitude.
The function returns the torque associated with the selected mode.}

\Revised{The active configuration is loaded from \mbox{\texttt{nullspace.conf}}. It uses
the combined damping and singular-value conditioning mode with the parameters}

\begin{equation}
d_{\mathrm{null}}
=
2.0\,\mathrm{N\,m\,s/rad},
\qquad
k_\sigma
=
1.0\,\mathrm{N\,m},
\label{eq:implementation_baseline_nullspace_torque_parameters}
\end{equation}

\begin{equation}
\alpha_{\mathrm{probe}}
=
0.08\,\mathrm{rad},
\qquad
\delta_\sigma
=
10^{-6},
\qquad
\rho
=
10^{-4}.
\label{eq:implementation_baseline_nullspace_sampling_parameters}
\end{equation}

\Revised{In \mbox{\cref{eq:implementation_baseline_nullspace_torque_parameters}},
\mbox{\(d_{\mathrm{null}}\)} is the null-space damping coefficient and
\mbox{\(k_\sigma\)} is the sigma-conditioning torque magnitude. In
\mbox{\cref{eq:implementation_baseline_nullspace_sampling_parameters}},
\mbox{\(\alpha_{\mathrm{probe}}\)} is the null-direction sampling angle and
\mbox{\(\delta_\sigma\)} is the sigma-comparison deadband. The relative
\mbox{\abbr{SVD}} tolerance is denoted by \mbox{\(\rho\)}.}

\Revised{During Cartesian pose hold, the operator can adjust the active null-space mode,
damping coefficient, conditioning-torque magnitude, and probe step. The
requested values are transferred through atomic variables and assigned inside
the callback. Live null-space tuning is associated with the standard Cartesian
pose hold, while the phase sequence and set-up-impedance hold use the
configuration loaded before the controller session.}

\section{Surface and Tool Geometry}
\label{sec:surface_task_plane}

\Revised{The mathematical definition of the surface task frame is given in
\mbox{\Cref{subsec:surface_task_frame}}. In the implementation, this frame is
constructed from the calibrated plane orientation and a reference direction for
\mbox{\(t_1\)}.
The resulting frame is then used for the tool-orientation target, the approach
direction, the phase-dependent gains, and the surface-relative evaluation
quantities.}


\subsection{Surface Task Frame}
\label{subsec:implemented_surface_task_frame}

\Revised{The plane configuration contains one surface point expressed in the robot base
frame, two surface-tilt angles, and a surface-frame reference direction
\mbox{\(a_s\)} used to define \mbox{\(t_1\)}. The parameter loader converts the
tilt angles to a unit surface normal \mbox{\(n_s\)}. The function
\mbox{\texttt{makeSurfaceFrame}} uses \mbox{\(a_s\)} to fix the in-plane
rotation of the surface frame.}


\Revised{The code variable \mbox{\texttt{R\_base\_surface}} corresponds to
\mbox{\(R_{\mathrm{surface}}\)} in Chapter~2. Its columns follow the fixed order}

\[
[\,t_1,\ t_2,\ n_s\,].
\]

\Revised{The configured surface-frame reference direction \mbox{\(a_s\)} is projected
onto the surface plane and normalised to obtain \mbox{\(t_1\)}. The second
tangent is then constructed as \mbox{\(t_2=n_s\times t_1\)}, completing the
right-handed surface frame in robot base coordinates. A fallback direction is
selected when \mbox{\(a_s\)} is approximately parallel to the surface normal
\mbox{\(n_s\)}.}

\Revised{The active configuration uses the calibrated surface point}

\[
p_s
=
\begin{bmatrix}
0.5153 & -0.1072 & 0.0031
\end{bmatrix}^{\top}\,\mathrm{m},
\]

\Revised{together with the calibrated surface tilts}

\[
\alpha_s=-1.585^\circ,
\qquad
\beta_s=+0.988^\circ.
\]

\Revised{The positive base-frame \mbox{\(x\)}-direction is used as the reference
direction for constructing \mbox{\(t_1\)}. The configuration
selector \mbox{\texttt{use\_start\_as\_surface\_point}} can alternatively assign the
captured controller start position to the runtime surface point. The active
configuration selects the calibrated point from \mbox{\texttt{surface.conf}}:}

\begin{center}
\begin{tabular}{ll}
\textbf{Start-position option} & Captured start position \(p_{\mathrm{start}}\) \\
\textbf{Configured-plane option} & Calibrated surface point \(p_s\) (active)
\end{tabular}
\end{center}

\Revised{The descent direction is defined once from the surface normal \mbox{\(n_s\)}:}

\[
-n_s.
\]

\Revised{It therefore points opposite to \mbox{\(n_s\)}, from the free-space starting region
toward the configured plane.}


\subsection{Surface-Relative Tool Orientation}
\label{sec:tool_orientation_given_surface}

\Revised{The controlled physical tool axis is configured in the end-effector frame.
During each callback, its current base-frame direction is obtained from}

\begin{minipage}[t]{\linewidth}
\begin{equation}
n_T=R_{\mathrm{EE}}n_{\mathrm{EE}}.
\label{eq:implementation_current_tool_normal}
\end{equation}
\end{minipage}

\Revised{The flat alignment direction is selected as either \mbox{\(+n_s\)} or \mbox{\(-n_s\)}
through \mbox{\texttt{tool\_}}\allowbreak \mbox{\texttt{axis\_}}\allowbreak \mbox{\texttt{target\_}}\allowbreak \mbox{\texttt{sign}}.
The configured angular offsets about
the two surface tangents are combined into one rotation vector and applied to
this flat direction:}

\begin{equation}
n_d
=\exp\!\left(
[\theta_{t_1}t_1+\theta_{t_2}t_2]_\times
\right)(\pm n_s).
\label{eq:implementation_tool_normal_target}
\end{equation}

\Revised{This construction permits the tool axis to be aligned with the plane or
assigned a commanded tool orientation offset about \mbox{\(t_1\)} and \mbox{\(t_2\)}. The shortest
rotation from the tool axis at the captured start orientation to the selected
target axis is then applied to the complete start orientation:}

\[
R_{\mathrm{start}}
\xrightarrow{\text{minimum rotation aligning }n_T\text{ with }n_d}
R_d.
\]

\Revised{When \mbox{\texttt{command\_tool\_twist}} is enabled, the rectangular-face long axis
provides an additional in-plane orientation reference. Its current direction
and the selected surface tangent are projected onto the plane perpendicular to
the desired tool axis. The configured normal-axis offset then determines the
desired twist about that axis.}


\Revised{For the centred rectangular face, rotations differing by \mbox{\(180^\circ\)} give
an equivalent face orientation. The implementation selects the equivalent
half-turn nearest to the captured start orientation, thereby reducing the
required orientation motion.}

\Revised{The active configuration defines the controlled axis as
\mbox{\(+z_{\mathrm{EE}}\)} and selects alignment toward the surface through}

\[
\texttt{tool\_axis\_target\_sign}=-1.
\]

\Revised{The commanded orientation contains an offset of \mbox{\(10^\circ\)} about \mbox{\(t_1\)},
\mbox{\(0^\circ\)} about \mbox{\(t_2\)}, and an in-plane twist of \mbox{\(90^\circ\)} about the
target tool axis. The twist command is enabled in
\mbox{\texttt{tool\_orientation.conf}}.}


\subsection{Rectangular Grinding Face and Clearance}
\label{sec:tool_contact_geometry}

\Revised{The contact geometry is represented by a rectangular face fixed in the
end-effector frame. Its centre, half-width vector, and half-length vector define
the four vertices:}

\begin{equation}
\left\{
r_{\mathrm{face,EE}}
\mathbin{\pm}r_{\mathrm{width,EE}}
\mathbin{\pm}r_{\mathrm{length,EE}}
\right\}.
\label{eq:implementation_tool_face_vertices}
\end{equation}

\Revised{The configured face centre is located \mbox{\(20\,\mathrm{mm}\)} along
\mbox{\(+z_{\mathrm{EE}}\)}. Its half-width and half-length are \mbox{\(20\,\mathrm{mm}\)}
along \mbox{\(x_{\mathrm{EE}}\)} and \mbox{\(60\,\mathrm{mm}\)} along
\mbox{\(y_{\mathrm{EE}}\)}, respectively. The represented contact face therefore
measures \mbox{\(40\,\mathrm{mm}\times120\,\mathrm{mm}\)}.}

\Revised{Before set-up, the controller transforms all four vertices to the base frame
and projects them onto the descent direction. The maximum projection identifies
the part of the face that leads during the approach.}


\Revised{The configured tie tolerance groups vertices whose projections differ from the
leading value by no more than this tolerance. The grouped vertices are
averaged, which permits nearly equal leading projections to represent an edge
or the complete face instead of a single corner. The configured tie tolerance is
\mbox{\(0.1\,\mathrm{mm}\)}.}

\Revised{The active configuration enables both contact-point control and
leading contact-point selection. The selected offset is transformed to the base frame to obtain the
current controlled contact point:}

\begin{equation}
p_g=p_{\mathrm{EE}}+R_{\mathrm{EE}}r_{g,\mathrm{EE}}.
\label{eq:implementation_contact_point_position}
\end{equation}

\Revised{The leading contact point is reevaluated while the tool is being oriented and
approached. On entry to set-up, its end-effector-frame offset is stored in
\mbox{\texttt{active\_tool\_contact\_offset\_ee}} and subsequently held constant during
set-up and grinding.}

\Revised{During surface approach, the clearance calculation distinguishes the exact
leading projection from the position of the averaged controlled contact point:}

\begin{center}
\begin{tabular}{p{0.27\textwidth}p{0.62\textwidth}}
\textbf{Foremost-face clearance} & Smallest normal separation between any face vertex and the plane \\
\textbf{Controlled-point height} & Signed normal coordinate of the averaged selected point
\end{tabular}
\end{center}

\Revised{The quantity \mbox{\texttt{height\_above\_surface}} represents the normal clearance
of the foremost point of the complete rectangular face. It provides the
geometric transition condition. The quantity
\mbox{\texttt{controlled\_point\_height}} is the signed height of the averaged
controlled contact point. Its projection onto the configured plane provides the
surface reference used by the subsequent set-up motion.}

\Revised{When the clearance condition is satisfied, the contact geometry and current
pose are captured:}

\begin{center}
\begin{tabular}{p{0.30\textwidth}p{0.59\textwidth}}
\textbf{Geometry} & Selected EE-frame point and its projection onto the plane \\
\textbf{Robot state} & Current TCP position and orientation \\
\textbf{Wrench reference} & Current model-estimated force and moment
\end{tabular}
\end{center}

\Revised{The internal variable \mbox{\texttt{first\_contact\_point}} stores the projected
clearance point on the configured plane. The live signed height determines
\mbox{\texttt{setup\_push\_start}}, which produces a continuous desired position when
the controller changes from approach to set-up.}

\Revised{During set-up, the desired position of the contact point is advanced from
this projected point along the descent direction. The contact target is then
converted to the corresponding TCP reference using the orientation captured at
the clearance transition:}

\begin{center}
\begin{tabular}{p{0.30\textwidth}p{0.59\textwidth}}
\textbf{Contact-point target} & Projected clearance point advanced along \(-n_s\) \\
\textbf{TCP target \(p_d\)} & Contact-point target less the stored EE-frame point offset
\end{tabular}
\end{center}

\Revised{This construction allows the translational impedance controller to command the
selected contact point while the Cartesian control law remains formulated at
the TCP.}

\]

\[

\]

\subsection{Calculation of Inertia-Scaled Damping}
\label{subsec:inertia_scaled_damping_calculation}

\Revised{Each phase first receives the damping matrices configured in the parameter
files. When inertia-scaled damping is enabled for a phase group, the controller
replaces these matrices with values calculated from the current
operational-space inertia \mbox{\(\Lambda\)}.}

\Revised{The joint-space inertia matrix \mbox{\(M\)} is obtained from the libfranka
model and factorised using a lower--diagonal--lower-transpose
(\mbox{\abbr{LDLT}}) decomposition,}

\[
M=LDL^\top,
\]

\Revised{where \mbox{\(L\)} is lower triangular and \mbox{\(D\)} is diagonal. Eigen's
\mbox{\texttt{LDLT}} implementation stores this factorisation and uses it to solve}

\[
MX=J^\top.
\]

\Revised{The solution matrix \mbox{\(X\)} is}

\[
X=M^{-1}J^\top,
\]

\Revised{without explicitly forming \mbox{\(M^{-1}\)}. The inverse operational-space
inertia \mbox{\(\Lambda^{-1}\)} is then constructed from}

\[
\Lambda^{-1}=JM^{-1}J^\top.
\]


\Revised{This calculation gives the regularised base-frame operational-space inertia
estimate \mbox{\(\Lambda_0\)}:}

\begin{equation}
\Lambda_0
=
\left(
JM^{-1}J^\top
+
10^{-9}I_6
\right)^{-1}.
\label{eq:implementation_cartesian_inertia}
\end{equation}

\Revised{The matrix is symmetrised before and after its factorisation. It is then
transformed from the robot base axes to the coordinate frame of the active
gain block:}

\begin{equation}
\Lambda
=T_R^\top\Lambda_0T_R,
\qquad
\lambda_i=\Lambda_{ii}.
\label{eq:implementation_directional_inertia}
\end{equation}

\Revised{The first three diagonal entries provide the directional translational
inertias, while the last three provide the directional rotational inertias.
For each direction \mbox{\(i\)}, the inertia-scaled damping coefficient
\mbox{\(d_{\mathrm{dir},i}\)} is calculated from}

\begin{equation}
d_{\mathrm{dir},i}
=
2\zeta\sqrt{\lambda_i k_i},
\label{eq:implementation_inertia_scaled_damping}
\end{equation}

\Revised{where \mbox{\(\lambda_i\)} is the corresponding directional Cartesian inertia,
\mbox{\(k_i\)} is the directional stiffness, and \mbox{\(\zeta\)} is the configured damping
ratio. For \mbox{\(\zeta=1\)}, the expression gives the critical-damping coefficient
of the corresponding decoupled direction.}

\Revised{The calculation is implemented independently for the three translational and
three rotational directions:}

\begin{equation*}
\operatorname{diag}\!\left(
d_{\mathrm{dir},1},d_{\mathrm{dir},2},d_{\mathrm{dir},3}
\right).
\end{equation*}

\Revised{The common upper bound is defined by
\mbox{\texttt{auto\_damping\_max}}. The parameter
\mbox{\texttt{auto\_}}\allowbreak \mbox{\texttt{damping\_}}\allowbreak \mbox{\texttt{min\_}}\allowbreak \mbox{\texttt{from\_}}\allowbreak \mbox{\texttt{manual}}
selects either zero or the
configured damping value as the lower bound.}

\Revised{The coordinate frame used for the inertia estimate follows the frame of the
corresponding stiffness matrix:}

\begin{itemize}
    \item \Revised{approach translation and rotation use the surface frame;}
    \item \Revised{set-up translation uses the selected base or surface frame, while
          set-up rotation uses the surface frame;}
    \item \Revised{Cartesian pose hold uses the robot base frame; and}
    \item \Revised{the phase gate uses base-frame translation and surface-frame
          rotation.}
\end{itemize}

\Revised{The damping matrices are cached by phase group. Entering tool orientation or
surface approach calculates the approach damping. Entering set-up,
grinding, or set-up-impedance hold calculates the set-up damping. Cartesian
pose hold uses its hold damping, while an active operator gate uses the
gate-hold damping. Leaving a phase group clears its cached state so that a
later entry uses the current robot configuration.}

\Revised{For the phase-gate hold, separate damping ratios are derived from the
configured translational and rotational gate-hold damping values. Cartesian pose hold can similarly derive one damping ratio from its configured
translational damping and apply it to the translational and rotational
inertia-scaled damping calculations.}

\Revised{The active configuration enables inertia-scaled damping for approach, set-up, and
the phase gates. Standard Cartesian pose hold uses its configured damping
matrices. The exact stiffness, damping-factor, and limiting values used during
the experiments are listed in \mbox{\Cref{ch:methodology}}.}

\Revised{When the inertia calculation satisfies the numerical validity checks, the
calculated damping matrices replace the configured matrices for the active
phase group. The configured matrices remain available as the initial and
fallback values.}

\section{Virtual Centre of Compliance}
\label{sec:self_alignment_virtual_center}

\Revised{The theoretical transformation from a centre-defined Cartesian impedance to
an equivalent TCP impedance is derived in
\mbox{\Cref{sec:coupled_pole_stiffness}}. The implementation applies this
transformation inside \mbox{\texttt{computeCartesianImpedanceWrench}}. The
phase-dependent translational and rotational gain blocks are first expressed
in the robot base frame and are then shifted from the selected virtual centre
of compliance \mbox{\(p_c\)} to the TCP.}

\Revised{The coupled branch is activated during set-up and during the dedicated
set-up-impedance hold mode:}

\begin{equation*}
\text{coupled branch}
\iff
p_c\text{ is enabled}\ \land\
\bigl(\text{set-up}\ \lor\ \text{set-up-impedance hold}\bigr).
\end{equation*}

\Revised{Tool orientation, surface approach, grinding, and standard Cartesian pose hold
therefore use the decoupled impedance branch. A pre-grinding confirmation gate
keeps \mbox{\texttt{ControlPhase::kSetup}}; the coupled set-up impedance consequently
remains active while the controller waits, and the penetration ramp continues
to advance.}

\Revised{The controller supports two definitions of the virtual centre. Both follow the
lever convention}

\[
r_c=p_{\mathrm{TCP}}-p_c
\]

\Revised{introduced in \mbox{\Cref{eq:pole_to_tcp_lever}}. The first definition specifies the
centre position relative to the TCP in end-effector coordinates. The second
specifies the lever \mbox{\(r_c\)} directly in surface coordinates.}


\Revised{For the tool-frame definition,
\mbox{\texttt{compliance\_}}\allowbreak \mbox{\texttt{center\_}}\allowbreak \mbox{\texttt{offset\_}}\allowbreak \mbox{\texttt{ee}}
represents
\mbox{\(p_c-p_{\mathrm{TCP}}\)}. The multiplication by \mbox{\(R_{\mathrm{EE}}\)} expresses
this offset in the robot base frame, while the negative sign converts it to
the implemented lever convention. Since the measured orientation
\mbox{\(R_{\mathrm{EE}}\)} is used during every callback, this lever follows the
current end-effector orientation.}

\Revised{For the surface-frame definition,
\mbox{\texttt{r\_}}\allowbreak \mbox{\texttt{tcp\_}}\allowbreak \mbox{\texttt{from\_}}\allowbreak \mbox{\texttt{compliance\_}}\allowbreak \mbox{\texttt{center\_}}\allowbreak \mbox{\texttt{surface}}
contains the components of
\mbox{\(r_c\)} along \mbox{\([t_1,t_2,n_s]\)}. Multiplication by
\mbox{\texttt{R\_base\_surface}} expresses the lever in the robot base frame. The
surface frame and configured lever remain fixed during one controller session,
so this definition produces a constant base-frame lever throughout set-up.}

\Revised{When virtual-compliance-centre control is enabled, the configuration loader
requires exactly one of these definitions:}

\begin{equation}
\text{tool-frame definition}\ \oplus\
\text{surface-frame definition}=\text{true},
\label{eq:implementation_compliance_definition_validation}
\end{equation}

\Revised{The function \mbox{\texttt{complianceShiftMatrix}} constructs the point-shift matrix
derived in \mbox{\Cref{eq:offset_adjoint}}. The skew-symmetric lever matrix occupies
the upper-right block because the Cartesian vectors follow the ordering
\mbox{\([\text{translation},\text{rotation}]\)}.}


\Revised{The phase-dependent \mbox{\(3\times3\)} translational and rotational matrices are
combined into centre-defined spatial gain matrices. The same congruence is
then applied independently to stiffness and damping:}

\begin{equation}
K_{\mathrm{TCP}}=\operatorname{Ad}^\top(r_c)K_c\operatorname{Ad}(r_c),
\qquad
D_{\mathrm{TCP}}=\operatorname{Ad}^\top(r_c)D_c\operatorname{Ad}(r_c).
\label{eq:implementation_shifted_impedance_matrices}
\end{equation}

\Revised{The function \mbox{\texttt{blockDiagonal}} places \mbox{\(K_p\)} and \mbox{\(D_p\)} in the
translational blocks and \mbox{\(K_R\)} and \mbox{\(D_R\)} in the rotational blocks. These
matrices have already been transformed into the frame selected for the active
phase. The subsequent congruence changes the impedance reference point while
preserving the selected principal-axis orientation.}

\Revised{The off-diagonal blocks generated by the point shift couple translation and
rotation. A translational displacement or velocity error can therefore
contribute to the commanded TCP moment, while a rotational error can
contribute to the commanded TCP force. The coupling disappears when the
configured lever is zero, in which case the shifted matrices reduce to their
block-diagonal form.}

\Revised{During set-up, the desired orientation remains the orientation captured at the
clearance transition. This orientation acts as a soft rotational reference
while the selected contact point is advanced into the surface. The resulting
rotation is determined by the coupled impedance, the contact wrench, the
directional stiffness, and the physical tool--surface interaction rather than
by a prescribed rotational trajectory.}

\Revised{The set-up and grinding phases share the same \mbox{\(3\times3\)} stiffness and
damping blocks. At the transition to grinding, the state machine assigns
\mbox{\texttt{ControlPhase::kGrinding}} before the Cartesian wrench \mbox{\(F\)} is evaluated
later in the same callback. The first grinding sample therefore uses the
decoupled branch. The implementation applies this change as a direct switch
from the shifted \mbox{\(6\times6\)} matrices to the decoupled gain blocks, while the
achieved penetration and desired orientation remain continuous across the
transition.}

\Revised{The set-up-impedance hold mode permits the translational stiffness,
rotational stiffness, commanded tilt, and compliance-centre coordinates to be
adjusted through the operator interface. Centre-position commands are entered
in end-effector coordinates, while lever commands are entered in surface
coordinates. An accepted update is converted to the selected internal
representation, after which the phase gains and inertia-scaled-damping cache are
rebuilt.}

\Revised{After set-up, the reporting module resolves the selected centre in both
end-effector and surface coordinates. It also evaluates the effective TCP
stiffness and damping matrices, the largest translation--rotation coupling
entry, and the eigenvalue ranges of the shifted matrices. These quantities
support verification of the configured lever, its sign, and the resulting
coupled impedance.}

\subsection{Tool Orientation}
\label{subsec:implementation_tool_orientation_phase}

\Revised{The tool-orientation phase maintains the captured start position while the
desired orientation is advanced toward the surface-relative target described

a rate-limited interpolation from the captured start orientation.}

\Revised{The transition condition is evaluated from two errors. The tool-axis error

the in-plane twist command is enabled, the remaining rotation about the target

\Revised{The configured minimum duration allows the orientation command to begin
settling before convergence is accepted. The timeout provides a second
transition path and allows the sequence to continue with the orientation
reached within the available interval. The external-wrench reference is
updated when surface approach begins.}

\subsection{Set-Up}
\label{subsec:implementation_setup_phase}

\Revised{The set-up phase advances the selected contact point from the projected surface
point into the plane. The scalar penetration begins at the signed contact-point
coordinate captured during the approach transition and progresses toward
\mbox{\texttt{setup\_}}\allowbreak \mbox{\texttt{push\_}}\allowbreak \mbox{\texttt{end}} at the configured speed.}


\Revised{The function \mbox{\texttt{setupPush}} integrates a constant signed
speed and clamps the result at the configured final penetration. It is
evaluated on the elapsed phase time, so the ramp runs whenever the set-up phase
is active. Reaching the clamp is what ends the advance, not leaving the
phase.}

\Revised{The desired orientation remains
\mbox{\texttt{R\_contact\_start}}, which is the orientation captured at the clearance
transition. The tool can consequently rotate relative to this soft reference
under the coupled impedance and the physical contact wrench.}

\Revised{During set-up, the changes in external force and moment are calculated relative
to the values captured at the approach transition:}

\begin{equation}
\Delta\hat f_{\mathrm{ext}}
=\hat f_{\mathrm{ext}}-\hat f_{\mathrm{ref}}.
\label{eq:implementation_external_force_change}
\end{equation}
\Added{This quantity is the complete model-estimated force-change vector in
base coordinates. Resolving it in the surface frame gives}

\begin{equation}
R_{\mathrm{surface}}^\top\Delta\hat f_{\mathrm{ext}}
=
\begin{bmatrix}
t_1^\top\Delta\hat f_{\mathrm{ext}} &
t_2^\top\Delta\hat f_{\mathrm{ext}} &
n_s^\top\Delta\hat f_{\mathrm{ext}}
\end{bmatrix}^{\!\top}.
\label{eq:implementation_external_force_surface_components}
\end{equation}

\Added{Its last component is a model-estimated normal-force change, not the
commanded normal force. The two signals and their sign convention are defined
separately in \mbox{\cref{eq:commanded_surface_wrench_components}}.}
The moment change is obtained analogously from the current model-estimated
moment and the moment stored at the clearance transition.

\Revised{The force change \mbox{\(\Delta\hat f_{\mathrm{ext}}\)} is recorded and
included in the set-up evaluation. The moment change governs the phase exit
after the configured minimum duration, and the set-up timeout provides the
alternative exit condition.}

\Revised{The moment is referenced to the TCP before it is compared with the
threshold, which is the term \mbox{\texttt{p\_EE.cross(df\_ext)}} above. The
estimated external moment is reported about the base origin, so the share the
force produces through the TCP position is removed first; what remains is
\mbox{\(M_{\mathrm{TCP}}\)}. \mbox{\Cref{subsec:setup_run_evaluation}} carries
the same moment on to the contact point.}

\Revised{Before continuing, the controller evaluates and prints the set-up result once.
This report includes the achieved pose, contact-point position, alignment change
\mbox{\(\Delta\theta_{\mathrm{align}}\)},
force and moment changes, moment transferred to the contact point, active
impedance matrices, and compliance-centre diagnostics.}

\Revised{When the pre-grinding gate is enabled, the controller remains in the set-up
phase after the exit condition has been reached:}

\[
\text{set-up phase remains active}
\qquad\text{until operator confirmation}.
\]

\Revised{The coupled set-up impedance stays active while the controller waits,
and so does the penetration ramp. The commanded depth therefore keeps advancing
until it reaches the configured final penetration, and the preload the tool
holds at the gate depends on how long the wait lasts. After confirmation, the
current penetration is stored in \mbox{\texttt{grind\_push}} and becomes the
normal preload of the grinding phase.}


\subsection{Grinding}
\label{subsec:implementation_grinding_phase}

\Revised{Grinding maintains the final set-up penetration. The controller can either add a
tangential sweep or maintain only the normal penetration.}

\Revised{For an active sweep, the selected tangent is obtained from the surface frame.
The scalar sweep trajectory is then added to the pressed contact-point reference:}

\begin{center}
\begin{tabular}{p{0.30\textwidth}p{0.59\textwidth}}
\hline
\textbf{Reference component} & \textbf{Implementation} \\
\hline
Normal component & Penetration captured at the end of set-up, applied along \mbox{\(-n_s\)}. \\
Tangential component & Smooth-step displacement along the selected surface tangent. \\
\hline
\end{tabular}
\end{center}

\Revised{The function \mbox{\texttt{grindSweep}} uses a fifth-order smooth-step trajectory.
The first stroke moves from the centre position to the positive amplitude.
Subsequent strokes alternate smoothly between the positive and negative
amplitudes with zero velocity at each reversal.}

\Revised{When the sweep is disabled, the reference is corrected only along the surface
normal \mbox{\(n_s\)}. Its tangential coordinates follow the current contact-point position,
which preserves the set-up penetration without imposing a tangential
trajectory.}

\Revised{Grinding uses the set-up stiffness and damping values. The Cartesian
impedance routine selects the decoupled branch after the phase has changed to
\mbox{\texttt{kGrinding}}, as described in
\mbox{\Cref{sec:self_alignment_virtual_center}}.}


\subsection{Pose Hold and Manual Guidance}
\label{subsec:implementation_hold_guidance_modes}

\Revised{The pose-hold state supports two impedance configurations. Standard pose hold
uses the dedicated hold gains, while set-up-impedance hold applies the set-up
gains and can keep the virtual centre of compliance \mbox{\(p_c\)}. Both modes regulate a
captured Cartesian pose.}

\Revised{When the set-up-impedance hold is selected during a run, the measured pose is
first captured as the current controller state. The reference is then moved
smoothly toward the pose at which the hold session began. Translation uses the
configured approach speed, while orientation uses the configured maximum
angular rate. After both references have reached their stored values, the
controller continues as a stationary hold.}

\Revised{Manual guidance can be entered from any impedance-controlled phase. The
controller then returns Coriolis compensation together with joint-space
damping:}

\mbox{\cref{eq:implementation_manual_guidance_torque}}.

\Revised{After operator confirmation, the measured position, orientation, joint
configuration, and the selected surface and external-wrench references are
recaptured. The controller then resumes the phase stored in
\mbox{\texttt{restart\_phase}}.}


\subsection{Run Termination}
\label{subsec:implementation_run_termination}

\Revised{The callback finishes normally when a positive experiment duration has elapsed
or the operator issues the stop command:}

\[
\text{finish callback}
\quad\Longleftarrow\quad
\text{configured duration reached or stop requested}.
\]

\Revised{The same stop signal is assigned when the maximum approach distance is reached.
Robot-side safety monitoring can also interrupt the torque-control session
through a libfranka exception. The subsequent error handling and collision
configuration are described in
\mbox{\Cref{sec:collision_behavior_safety}}.}

\section{Robot Preparation and Safety Handling}
\label{sec:collision_behavior_safety}

\Revised{Robot preparation is performed before the real-time impedance callback begins.
It includes the initial FCI connection, error recovery, collision
configuration, motion to the selected initial posture, and the optional
gripper and tool-transfer actions.}

\subsection{Robot Connection and Collision Configuration}
\label{subsec:robot_collision_configuration}

\Revised{At program start, the robot address is read from the controller configuration
and used to establish the FCI connection. Error recovery is requested
before the collision behaviour and robot model are loaded:}

\begin{equation}
\text{FCI connection}
\longrightarrow
\text{error recovery}
\longrightarrow
\text{collision configuration}
\longrightarrow
\text{robot model}.
\label{eq:implementation_robot_initialisation_sequence}
\end{equation}

\Revised{Failure of the recovery request terminates the program before a motion command
is issued. Further recovery or unlocking is then performed through Franka
Desk before restarting the controller.}

\Revised{The function \mbox{\texttt{configureCollisionBehavior}} first applies the standard
robot behaviour provided by the libfranka example utilities. The custom
thresholds defined in \mbox{\texttt{safety.conf}} are subsequently assigned when
their selector is enabled:}

\begin{center}
\begin{tabular}{p{0.27\textwidth}p{0.62\textwidth}}
\hline
\textbf{Threshold group} & \textbf{Assignment} \\
\hline
Joint torque & The selected scalar is repeated for all seven joints. \\
Cartesian force and moment & The selected scalar is repeated for all six wrench components. \\
Lower and upper limits & Identical arrays are supplied to both interfaces. \\
\hline
\end{tabular}
\end{center}

\Revised{The two joint-torque parameters define the acceleration-phase and nominal
thresholds in \mbox{\(\mathrm{N\,m}\)}. Each scalar is assigned uniformly to all
seven joints. The two Cartesian parameters are similarly assigned to all six
force and moment components in the acceleration and nominal phases. The same
array is passed for the lower and upper threshold of each group.}

\Revised{The controller returns the calculated joint torque \mbox{\(\tau_{\mathrm{cmd}}\)} directly to libfranka:}

\begin{equation}
\texttt{Torques}\!\left(\tau_{\mathrm{cmd}}\right)
\longrightarrow \text{libfranka}.
\label{eq:implementation_direct_torque_return}
\end{equation}

\Revised{The application transfers the calculated Cartesian wrench \mbox{\(F\)},
null-space torque \mbox{\(\tau_{\mathrm{null}}\)}, and complete joint-torque command
\mbox{\(\tau_{\mathrm{cmd}}\)} directly to libfranka. Robot-side
monitoring and the configured collision behaviour provide command boundedness
and motion interruption.}


\subsection{Initial Joint Posture}
\label{subsec:initial_joint_posture}

\Revised{The parameter \mbox{\texttt{q\_init\_case}} selects one of the joint configurations
stored in \mbox{\texttt{initial\_}}\allowbreak \mbox{\texttt{pose.conf}}. The corresponding seven
joint angles
are assigned to \mbox{\texttt{q\_init}} when the configuration is loaded.}

\Revised{The phase sequence and both Cartesian hold modes begin from this posture. The
start-up interface moves the robot to it using the libfranka
\mbox{\texttt{MotionGenerator}}:}

\[
\text{current posture}
\longrightarrow
\text{configured initial posture}
\qquad\text{with speed factor }0.4.
\]

\Revised{The speed factor is fixed at \mbox{\(0.4\)} for this preparation motion. A local flag
records whether the posture has already been reached and prevents repeated
motion when the operator performs several preparation actions before selecting
a run mode.}

\Revised{Selection of the phase sequence, standard pose hold, or set-up-impedance hold
calls \mbox{\texttt{ensure\_q\_init}}. Manual guidance forms the alternative start
path and begins from the current robot pose. The guided pose is captured before
the subsequent sequence or hold mode starts.}


\subsection{Gripper Verification}
\label{subsec:gripper_verification}

\Revised{The start-up interface provides separate commands for opening, grasping, and
recalibrating the Franka Hand. Each action reads the gripper state before and
after the command and verifies the resulting finger position.}

\Revised{For opening, successful verification requires the libfranka motion command to
finish, the calibrated maximum stroke to contain the requested width, and the
measured final width to reach the target within a \mbox{\(2\,\mathrm{mm}\)}
tolerance. Grasp verification requires the grasp command to finish, the
\mbox{\texttt{is\_grasped}} flag to be active, and the measured width to lie within
the configured inner and outer tolerances.}

\Revised{Before either action, the reported maximum finger width is compared with the
largest width used by the controller. A smaller calibrated stroke indicates
that gripper homing was performed while an object restricted the finger
motion. The start-up interface then requests recalibration with empty fingers.}

\Revised{A configured gripper action can also be executed immediately
before torque control. A previously verified manual action is kept and is
therefore not repeated. When the requested action is grasping, an already
verified tool grasp is also kept:}

\begin{equation}
\text{start-up gripper action}
=
\begin{cases}
\text{retain verified state}, & \text{requested state already verified},\\
\text{execute and verify action}, & \text{otherwise}.
\end{cases}
\label{eq:implementation_gripper_action_selection}
\end{equation}

\Revised{The parameter
\mbox{\texttt{abort\_}}\allowbreak \mbox{\texttt{on\_}}\allowbreak \mbox{\texttt{gripper\_}}\allowbreak \mbox{\texttt{action\_}}\allowbreak \mbox{\texttt{failure}}
determines whether
a failed gripper action terminates the program or allows the selected
controller session to continue.}


\subsection{Tool Transfer}
\label{subsec:tool_transfer}

\Revised{The controller also provides an optional sequence for collecting the tool from
its holder or returning it. The holder configuration is represented by the
joint posture \mbox{\texttt{q\_pickup}}. A stand-off posture is calculated at the same
end-effector orientation and at the configured distance along
\mbox{\(-z_{\mathrm{EE}}\)}.}

\Revised{The stand-off configuration is obtained through damped least-squares inverse
kinematics. Each iteration calculates the position error \mbox{\(e_p\)} and
orientation error \mbox{\(e_R\)}, forms the current end-effector Jacobian
\mbox{\(J(q)\)}, and limits the joint-update norm. The
resulting posture is accepted only when all joints remain within their
configured limits with a \mbox{\(0.05\,\mathrm{rad}\)} margin.}

\Revised{After successful calculation, the tool-transfer path is executed as}

\[
q_{\mathrm{init}}
\longrightarrow
q_{\mathrm{above}}
\longrightarrow
q_{\mathrm{pickup}}
\longrightarrow
q_{\mathrm{above}}.
\]

\Revised{The corresponding implementation is:}

\begin{figure}[H]
  \centering
  \resizebox{0.72\textwidth}{!}{\input{figures/tool_transfer_flow.tex}}
  \caption{Tool collection and return sequence.}
  \label{fig:tool_transfer_flow}
\end{figure}

\Revised{When collecting the tool, the gripper is opened and verified before the arm
moves toward the holder. At the pickup posture, the selected gripper action is
executed and verified before the robot returns to the stand-off posture.}


\subsection{Exception Handling}
\label{subsec:controller_exception_handling}

\Revised{Robot communication, motion-generation, and torque-control errors are reported
through \mbox{\texttt{franka::Exception}}. Configuration, file, and numerical errors
are reported through \mbox{\texttt{std::exception}}. Both exception types leave the
active control operation and terminate the program with an error code.}

\Revised{A robot-side safety event can therefore end the torque callback independently
of the controller phase or experiment timer. The corresponding exception is
reported after control has stopped, and the robot is recovered through Franka
Desk before a new program execution.}

\section{Data Recording and Run Evaluation}
\label{sec:recorded_signals}

\Revised{The controller records the quantities required for the subsequent run
evaluation in a bounded in-memory ring buffer. Its memory is allocated before
\mbox{\texttt{robot.control}} starts, so the real-time callback performs no dynamic
buffer growth.}


\Revised{The parameter \mbox{\texttt{log\_}}\allowbreak \mbox{\texttt{every\_}}\allowbreak \mbox{\texttt{n\_}}\allowbreak \mbox{\texttt{cycles}}
defines the sampling interval in
control cycles, while \mbox{\texttt{max\_}}\allowbreak \mbox{\texttt{log\_}}\allowbreak \mbox{\texttt{rows}} defines
the maximum number of
samples stored in memory. The active configuration records every control cycle
and allocates space for \mbox{\(120\,000\)} rows.}

\Revised{The structure \mbox{\texttt{LogData}} stores one sample of the measured state,
controller reference, calculated command, and active controller mode. The
recorded quantities are summarised in
\mbox{\cref{tab:recorded_controller_signals}}.}

\begin{table}[H]
\centering
\caption{Signal groups stored during the real-time control loop.}
\label{tab:recorded_controller_signals}
\begin{tabular}{p{0.27\textwidth}p{0.65\textwidth}}
\hline
\textbf{Signal group} & \textbf{Recorded quantities} \\
\hline
Time and controller state
&
Run time, encoded control phase, and encoded null-space mode.
\\[1mm]

TCP state and reference
&
Measured and desired TCP positions, translational and rotational errors,
measured linear and angular velocities, and desired linear velocity.
\\[1mm]

Tool and surface geometry
&
Current controlled contact-point position, contact-point offset in the end-effector
frame, projected clearance point, TCP position at the clearance transition,
desired contact target, and virtual surface penetration.
\\[1mm]

Alignment
&
Tool-axis alignment-error components along
\([t_1,t_2,n_s]\) and their Euclidean norm.
\\[1mm]

Cartesian wrench
&
Commanded and model-estimated external wrenches, including the
clearance-transition reference for the latter.
\\[1mm]

Null-space controller
&

null-space torque.
\\[1mm]

Disturbance experiment
&
Disturbance scale, torque-limit scale, force-application point, commanded

\\[1mm]

\\
\hline
\end{tabular}

\Revised{The internal variables and CSV columns named
\mbox{\texttt{first\_}}\allowbreak \mbox{\texttt{contact\_}}\allowbreak \mbox{\texttt{tcp}} and
\mbox{\texttt{first\_}}\allowbreak \mbox{\texttt{contact\_}}\allowbreak \mbox{\texttt{point}} refer to the
geometric clearance transition described in
\mbox{\Cref{subsec:implementation_surface_approach_phase}}. They represent the
captured TCP position and projected contact point at this transition,
rather than a force-detected contact event.}

\Revised{The selected values are copied into the current ring-buffer row at the
configured sampling interval:}

\begin{equation}
\text{ring-buffer row}
\leftarrow
\{\text{state},\text{reference},\text{error},\text{wrench},
\text{phase},\text{torque}\}.
\label{eq:implementation_log_sample}
\end{equation}

\Revised{The current implementation represents the null-space action through the active
mode, damping coefficient, and resulting torque norm. These quantities permit
the secondary torque to be distinguished from the Cartesian and disturbance
contributions during post-processing.}

\Revised{After assigning one row, the write index is advanced cyclically:}

\[
\text{next write index}
=
(\text{current write index}+1)\bmod\text{buffer capacity}.
\]

\Revised{Once the allocated capacity is reached, new samples replace the oldest rows.
The buffer therefore stores the most recent
\mbox{\texttt{max\_}}\allowbreak \mbox{\texttt{log\_}}\allowbreak \mbox{\texttt{rows}} samples instead of increasing
its memory requirement
during control.}


\subsection{Chronological Reconstruction and CSV Output}
\label{subsec:chronological_log_output}

\Revised{After the torque callback has finished, the ring-buffer contents are converted
to chronological order. When the buffer has wrapped, the oldest stored
sample begins at \mbox{\texttt{log\_}}\allowbreak \mbox{\texttt{write\_}}\allowbreak \mbox{\texttt{index}}:}

\begin{center}
\begin{tabular}{p{0.27\textwidth}p{0.62\textwidth}}
\hline
\textbf{Buffer state} & \textbf{Read order} \\
\hline
Not wrapped & From the first row to the current write position. \\
Wrapped & From the current write position to the end, then from the first row back to that position. \\
\hline
\end{tabular}
\end{center}

\Revised{The ordered samples and final controller state are returned in a
\mbox{\texttt{RunResult}}. File output is subsequently performed by
\mbox{\texttt{writeRunLogs}}, outside the real-time callback:}

\begin{equation}
\text{ordered samples}
\longrightarrow
\text{CSV output}
\longrightarrow
\text{terminal run summary}.
\label{eq:implementation_post_run_output}
\end{equation}

\Revised{The CSV writer creates the parent output directory when required and uses a
fixed column order. Cartesian positions, velocities, forces, moments,
disturbances, and joint torques \mbox{\(\tau\)} are written in their stored SI units.
Angular deviations are converted from radians to degrees for the output file.}

\Revised{The CSV writer calculates each external-wrench change by subtracting
the stored reference:}

\begin{center}
\begin{tabular}{p{0.30\textwidth}p{0.59\textwidth}}

therefore recorded as separate quantities. The former is generated by the

\Revised{When several controller sessions are executed without restarting the program,
the session number is inserted before the CSV filename extension:}

\[
\texttt{name.csv}
\longrightarrow
\texttt{name\_s2.csv},\ \texttt{name\_s3.csv},\ \ldots
\]

\Revised{For example, a second session based on
\mbox{\texttt{controller\_}}\allowbreak \mbox{\texttt{log.csv}} is written as
\mbox{\texttt{controller\_}}\allowbreak \mbox{\texttt{log\_}}\allowbreak \mbox{\texttt{s2.csv}}.}


\subsection{Set-Up Evaluation}
\label{subsec:setup_run_evaluation}

\Revised{A dedicated set-up report is generated once when the moment threshold or
set-up timeout is reached. The report captures the final TCP pose, contact-point
position, external wrench change, clearance-transition
references, active gain matrices, and set-up termination condition.}

\Revised{A moment depends on the point it is referred to. The reported one is
referred to the contact point, not to the TCP. \mbox{\(M_{\mathrm{TCP}}\)} is
the estimated external moment about the TCP, and
\mbox{\(r_{\mathrm{contact}}\)} the lever between the two points defined in
\mbox{\cref{eq:contact_lever_definition}}. The transfer is}

\begin{equation}
M_{\mathrm{contact}}
=
M_{\mathrm{TCP}}
+
r_{\mathrm{contact}}\times\Delta\hat f_{\mathrm{ext}}.
\label{eq:contact_moment_transfer}
\end{equation}

\Revised{\mbox{\(\Delta\hat f_{\mathrm{ext}}\)} is the model-estimated external
force, less the clearance-transition reference. \mbox{\(M_{\mathrm{TCP}}\)} is
the corresponding moment change. Force does not depend on the reference point
and carries no point subscript. The cross product removes the share the force
produces through the lever. What remains is the moment the contact itself
applies.}

\Revised{The lever \mbox{\(r_{\mathrm{contact}}\)} is not the compliance-centre
lever \mbox{\(r_c\)}. It follows from the tool geometry and enters the
evaluation only. \mbox{\(r_c\)} shapes the commanded wrench through
\mbox{\(\mathrm{Ad}(r_c)\)}. It reaches the measurement through the contact,
so the two never share an expression.}


\Revised{The terminal set-up report contains:}

\begin{itemize}
    \item \Revised{the set-up termination condition and phase duration;}
    \item \Revised{the external-force and external-moment changes;}
    \item \Revised{the TCP and contact-point displacements from the clearance transition;}
    \item \Revised{the tool-alignment error before and after set-up;}
    \item \Revised{the alignment-error components along \mbox{\(t_1\)}, \mbox{\(t_2\)}, and \mbox{\(n_s\)};}
    \item \Revised{the force, moment, displacement, and rotation resolved in the surface
          frame; and}
    \item \Revised{the active translational and rotational stiffness and damping
          matrices.}
\end{itemize}

\Revised{The displayed force--displacement and moment--angle ratios provide a
pointwise diagnostic of the completed set-up state. They are calculated only
when the corresponding displacement or rotation exceeds its numerical
minimum.}

\Revised{When compliance-centre diagnostics are enabled, the report additionally
resolves \mbox{\(r_c\)} in surface coordinates and \mbox{\(p_c\)} in end-effector
coordinates. It reconstructs the shifted TCP stiffness and damping matrices
and reports their diagonal entries, largest translation--rotation coupling
terms, and eigenvalue ranges. The complete \mbox{\(6\times6\)} matrices can also be
printed for verification of the configured lever and gain transformation.}

\Revised{The final post-run summary displays the joint displacement between the start
and end configurations, the desired and measured final TCP positions, the
final translational and rotational errors, and the path of the generated CSV
file.}

\Revised{The controller implementation described in this chapter forms the basis of
all reported experiments. \mbox{\Cref{ch:methodology}} presents the calibration
procedure, the controller parameters used during the measurements, the varied
experimental conditions, and the quantities derived from the recorded
signals.}
