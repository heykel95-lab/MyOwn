\chapter{Controller Design and Real-Time Implementation}
\label{ch:implementation}

\Added{The controller was implemented in C++, using libfranka for
communication with the Franka Control Interface and Eigen for matrix
operations. At the nominal control period of \mbox{\(1\,\mathrm{ms}\)}, each
callback evaluates the Cartesian impedance wrench, the optional virtual
\mbox{\abbr{CoC}} transformation, and the null-space torque.}


\section{Controller Architecture and Real-Time Control Cycle}
\label{sec:software_architecture}
\label{sec:real_time_control_loop}

The software separates session preparation, real-time control, and
post-processing. Before a controller session, the program reads and validates
the complete parameter set, establishes the \mbox{\abbr{FCI}} connection,
requests robot error recovery, applies the selected collision behaviour, loads
the robot model, and allocates the logging buffer. During torque control, the
real-time callback operates only on the prepared configuration, preallocated
state, robot-state data, model quantities, and non-blocking operator requests.
File output and experiment evaluation follow after torque control has stopped.

A separate keyboard thread receives operator requests and transfers them
through atomic variables, so terminal input stays outside the real-time
callback. The parameter file is read again before each session, which permits
controller settings to be changed between experiments.

The operating-state flow begins with robot recovery and controller selection,
as shown in \mbox{\Cref{fig:controller_state_flow}}. A successful recovery
opens the selection state. Inputs \texttt{s}, \texttt{h}, \texttt{t}, and
\texttt{g} select the Surface-Contact Sequence, Cartesian Pose Hold,
Contact-Impedance Hold, and Manual Guidance, respectively. An unsuccessful
recovery ends the program. Operator stop, a configured experiment-duration
limit, a robot-side error or reflex, and a communication or control exception
provide the common transition from any active controller state to Stop.

\Added{Libfranka reports robot-side errors and reflexes across its monitored
conditions. By contrast, communication and control exceptions form the
application-side category.}

Contact-Impedance Hold retains the captured Cartesian pose with the impedance
used for Contact Establishment. Its connection to the surface-contact sequence
is shown in \mbox{\Cref{fig:phase_flow_chart}}.

\mbox{\Cref{fig:controller_block_diagram}} shows the computations performed
during one real-time control cycle. The active controller state supplies the
desired position \mbox{\(p_d\)}, orientation \mbox{\(R_d\)}, and linear
velocity \mbox{\(\dot p_d\)}. The robot state supplies the measured
\mbox{\(p_{\mathrm{EE}}\)}, \mbox{\(R_{\mathrm{EE}}\)},
\mbox{\(\dot p_{\mathrm{EE}}\)}, and \mbox{\(\omega_{\mathrm{EE}}\)}
for feedback.

The Cartesian pose error and the measured velocities determine the impedance
wrench \mbox{\(F=[f^\top,m^\top]^\top\)} according to
\mbox{\Cref{subsec:cartesian_pose_error,sec:cartesian_impedance_control}}.
The Jacobian transpose maps this wrench to
\mbox{\(\tau_{\mathrm{cart}}\)}. The secondary null-space torque
\mbox{\(\tau_{\mathrm{null}}\)} and model Coriolis contribution
\mbox{\(\tau_c(q,\dot q)\)} are then added before the commanded joint torque
\mbox{\(\tau_{\mathrm{cmd}}\)} is returned to libfranka.

During Contact Establishment, the controller keeps \mbox{\(R_d\)} fixed at
the orientation captured at the clearance transition. The measured
end-effector rotation is therefore the contact response relative to this fixed
entry reference.

\Added{The end-effector pose supplied by the robot state provides
\mbox{\(p_{\mathrm{EE}}\)} and \mbox{\(R_{\mathrm{EE}}\)} directly.}

The rotational error \mbox{\(e_R\)} can be resolved in the surface frame so
that only the selected rotational components contribute to the rotational
spring term. The resulting error is then transformed back to the base frame,
while the rotational damping continues to use the measured angular velocity.
Depending on the active controller state, the impedance is defined either
directly at the TCP or about a displaced virtual \abbr{CoC}. In both cases, the
resulting Cartesian wrench is mapped to the joint-torque command through the
same torque formulation.

The complete impedance-controlled command follows
\mbox{\Cref{eq:nullspace_complete_torque_command}}.

Here \mbox{\(\tau_{\mathrm{null}}\)} is the secondary null-space torque of
\mbox{\Cref{subsec:complete_nullspace_torque}} and
\mbox{\(\tau_c(q,\dot q)\)} is the Coriolis and centrifugal contribution
obtained from the libfranka model. The \mbox{\abbr{FCI}} supplies gravity
compensation for the external joint-torque command, as described in
\mbox{\Cref{subsec:coriolis_gravity_compensation}}. The null-space pose-hold
experiment of \mbox{\Cref{sec:nullspace_hold_study}} adds an
experiment-specific disturbance torque.

The implemented controller is used in two configurations in this thesis. The
surface-contact configuration generates a state-dependent Cartesian reference
for Tool Orientation, Surface Approach, Contact Establishment, and the
subsequent Grinding state. The Cartesian pose-hold configuration is used for
the separate null-space investigation of \mbox{\Cref{sec:nullspace_hold_study}}.
Both configurations execute the same real-time control cycle and differ in the
generated reference and the active impedance.


\section{Surface-Contact Sequence}
\label{sec:implemented_configurations}
\label{subsec:implementation_contact_sequence}
\label{sec:control_phases}

A surface-contact experiment follows the state path drawn in
\mbox{\Cref{fig:phase_flow_chart}}. It begins either after the robot reaches
the stored initial joint configuration \mbox{\(q_{\mathrm{init}}\)}, or from
a configuration reached in Manual Guidance, where input \texttt{s} starts the
sequence from the current \mbox{\(q\)} and input \texttt{q} stores that
configuration as \mbox{\(q_{\mathrm{init}}\)} for a later session. The
sequence then progresses through Tool Orientation, Surface Approach, the
optional Pre-Contact Hold, Contact Establishment, the optional Pre-Grinding
Hold, and Grinding.

Tool Orientation ends after its minimum duration, when the configured
orientation criteria are satisfied or the orientation timeout is reached.
Surface Approach ends when the minimum tool clearance reaches
\mbox{\(h_{\mathrm{clearance}}\)}; reaching the maximum approach distance
first terminates the experiment. Each optional hold is skipped when disabled,
and otherwise waits for operator confirmation. Contact Establishment ends when
the moment-change criterion is satisfied after the minimum duration, or when
its independent timeout is reached.

During active control, operator input \texttt{g} enters Manual Guidance. The
robot can then be moved to a new configuration, and input \texttt{p} captures
the reached pose before returning to the controller from which Manual Guidance
was entered. The surface-contact sequence restarts at Tool
Orientation, whereas either Cartesian hold configuration adopts the captured
pose as its new held reference.

Operator input \texttt{t} enters Contact-Impedance Hold from the sequence.
That state retains the current Cartesian pose while \mbox{\(K_p\)},
\mbox{\(K_R\)}, or \mbox{\(r_c\)} is set for the next sequence. Input
\texttt{s} then restarts the sequence at Tool Orientation.

\subsection{Surface Frame, Tool Reference, and Tool Geometry}
\label{subsec:implemented_surface_task_frame}
\label{sec:tool_orientation_given_surface}
\label{sec:surface_task_plane}

The controller defines the surface frame \mbox{\(\{S\}\)} from the configured
surface point \mbox{\(p_s\)}, the surface normal \mbox{\(n_s\)}, and a
configured first-tangent hint. The point \mbox{\(p_s\)} defines the origin of
the configured surface, and \mbox{\(n_s\)} defines its normal direction. The
hint is projected onto the surface plane and normalised to obtain
\mbox{\(t_1\)}, as in \mbox{\Cref{subsec:surface_task_frame}}. When the hint
lies close to \mbox{\(n_s\)}, the controller applies a fallback direction. The
second tangent \mbox{\(t_2=n_s\times t_1\)} completes the right-handed surface
frame.

The resulting directions \mbox{\(t_1\)}, \mbox{\(t_2\)}, and \mbox{\(n_s\)}
define the approach direction \mbox{\(-n_s\)}, the surface-relative orientation
reference, and the principal directions of the Cartesian stiffness and damping
matrices. The same frame expresses a surface-fixed \abbr{CoC} displacement and
resolves the experimental quantities.

The tool-face normal is calibrated once in end-effector coordinates. During
control, the measured end-effector orientation transforms it into the robot
base frame:

\begin{equation}
n_{\mathrm{Tool}}=R_{\mathrm{EE}}n_{\mathrm{Tool,EE}}.
\label{eq:implementation_current_tool_normal}
\end{equation}

The configured pre-contact orientation offset is represented by the
tangent-plane rotation vector

\begin{equation}
\theta_{\mathrm{offset}}
=
\theta_{\mathrm{offset},t_1}t_1
+
\theta_{\mathrm{offset},t_2}t_2
\in\mathbb{R}^3.
\label{eq:implementation_tilt_rotation_vector}
\end{equation}

Its magnitude \mbox{\(\lVert\theta_{\mathrm{offset}}\rVert\)} defines the
angular offset relative to the configured surface-parallel orientation. For a
non-zero offset, the corresponding unit rotation axis is

\begin{equation}
u_{\mathrm{offset}}
=
\frac{\theta_{\mathrm{offset}}}{\lVert\theta_{\mathrm{offset}}\rVert},
\label{eq:implementation_offset_rotation_axis}
\end{equation}

and the axis--angle relation of \mbox{\Cref{eq:rodrigues_formula}} gives

\[
R_{\mathrm{offset}}
=
R\!\left(u_{\mathrm{offset}},\lVert\theta_{\mathrm{offset}}\rVert\right).
\]

For \mbox{\(\theta_{\mathrm{offset}}=0\)}, the controller sets
\mbox{\(R_{\mathrm{offset}}=I\)}. The rotation-vector representation allows
offsets about either surface tangent and about intermediate directions in the
tangent plane.

Because \mbox{\(n_s\)} points from the surface towards free space, a tool face
parallel to the configured plane has the tool-normal direction
\mbox{\(-n_s\)}. Applying the configured offset gives the desired tool-normal
direction

\begin{equation}
n_d
=
R_{\mathrm{offset}}\left(-n_s\right).
\label{eq:implementation_tool_normal_target}
\end{equation}

The controller calculates the shortest rotation from the tool direction
captured at state entry to \mbox{\(n_d\)}, and applies that rotation to the
complete captured end-effector orientation. An optional spin command about the
desired tool axis additionally fixes the in-plane orientation of the
rectangular tool face. A centred rectangle has equivalent orientations
separated by a half-turn about its normal, so the controller selects the
equivalent target orientation closest to the captured start orientation.
\mbox{\Cref{ch:methodology}} specifies the orientation settings used in the
experiments.

The controller represents the tool face as a rectangle fixed in the
end-effector frame, drawn in \mbox{\Cref{fig:face_feature_selection}}. Its
calibrated centre offset \mbox{\(r_{\mathrm{face,EE}}\)}, half-width vector
\mbox{\(r_{\mathrm{width,EE}}\)}, and half-length vector
\mbox{\(r_{\mathrm{length,EE}}\)} define the four corner offsets

\begin{equation}
r_{i,\mathrm{EE}}\in
\left\{
r_{\mathrm{face,EE}}
\mathbin{\pm}r_{\mathrm{width,EE}}
\mathbin{\pm}r_{\mathrm{length,EE}}
\right\}.
\label{eq:implementation_tool_face_vertices}
\end{equation}

\label{sec:tool_contact_geometry}%
These offsets are measured from the TCP, which coincides with the end-effector
origin in the implemented model, \mbox{\(p_{\mathrm{TCP}}=p_{\mathrm{EE}}\)}.
During Surface Approach the four corners determine the minimum clearance of the
rectangular tool face and the geometric tool point used to construct the
Contact Establishment trajectory.

\subsection{Tool Orientation}
\label{subsec:implementation_tool_orientation_phase}

\Added{The Tool Orientation state rotates the tool to the configured
pre-contact orientation while maintaining the TCP position captured at state
entry. A zero orientation offset aligns the tool face parallel to the
configured surface plane. A non-zero offset produces the corresponding
surface-relative tool direction before Surface Approach begins.}

\Added{The desired orientation follows a rate-limited interpolation from the
captured start orientation to the complete target orientation constructed from
\mbox{\Cref{eq:implementation_tool_normal_target}} and the optional spin
command. The controller evaluates the tool-axis error
\mbox{\(\theta_{\mathrm{app,err}}\)}, the angle between the measured and
desired tool axes. When a spin angle is configured, it also evaluates the
remaining spin error about the desired tool axis.}

\Added{After the configured minimum duration, the state advances to Surface
Approach when all enabled orientation errors lie within their respective
tolerances. The tool-axis error is compared with
\mbox{\(\varepsilon_{\mathrm{app}}\)}, and the spin error with its separate
configured tolerance. The orientation timeout \mbox{\(t_{\mathrm{end}}\)}
supplies the alternative transition. The end-effector orientation reached at
this transition is retained throughout Surface Approach.}

\subsection{Surface Approach, Clearance and Tool-Point Selection}
\label{subsec:implementation_surface_approach_phase}
\label{subsec:implementation_clearance_detection}

Surface Approach moves the TCP towards the configured plane along
\mbox{\(-n_s\)}. The controller captures the TCP position
\mbox{\(p_{\mathrm{TCP,start}}\)} at the beginning of the state, at time
\mbox{\(t_{\mathrm{app},0}\)}. The commanded approach distance is

\begin{equation}
s_{\mathrm{app}}(t)
=
\begin{cases}
v_{\mathrm{app}}\left(t-t_{\mathrm{app},0}\right),
& t_{\mathrm{app},0}\leq t<t_{\mathrm{app,max}},\\[4pt]
s_{\mathrm{app,max}}, & t\geq t_{\mathrm{app,max}},
\end{cases}
\label{eq:implementation_approach_coordinate}
\end{equation}

where \mbox{\(v_{\mathrm{app}}\)} is the configured approach speed,
\mbox{\(s_{\mathrm{app,max}}\)} the maximum approach distance, and
\mbox{\(t_{\mathrm{app,max}}\)} the instant at which the ramp reaches that
distance. Both configured values are listed in
Table~\ref{tab:experimental_phase_parameters}. The desired TCP position is

\begin{equation}
p_d(t)=p_{\mathrm{TCP,start}}-s_{\mathrm{app}}(t)n_s.
\label{eq:implementation_approach_reference}
\end{equation}

During the linear part of the trajectory, the desired TCP velocity is
\mbox{\(\dot p_d(t)=-v_{\mathrm{app}}n_s\)}. After
\mbox{\(s_{\mathrm{app,max}}\)} is reached, the desired position remains
constant and \mbox{\(\dot p_d=0\)}. Reaching the maximum approach distance
before the clearance criterion is satisfied terminates the experiment.

For an inclined tool face, the point closest to the plane can lie considerably
closer than the TCP. The controller therefore calculates the positions of all
four tool-face corners in every control cycle. The base-frame position of
corner \mbox{\(i\)} is

\begin{equation}
p_i(t)
=
p_{\mathrm{TCP}}(t)+R_{\mathrm{EE}}(t)r_{i,\mathrm{EE}}.
\label{eq:implementation_corner_position}
\end{equation}

Its surface-normal clearance from the configured plane is

\begin{equation}
h_i(t)
=
n_s^\top\left(p_i(t)-p_s\right).
\label{eq:implementation_corner_clearance}
\end{equation}

Because \mbox{\(n_s\)} points towards free space, a smaller value of
\mbox{\(h_i\)} places the corner closer to the plane. The TCP position and the
surface point contribute the same term to all four clearances, so the
implementation compares the rotated corner offsets directly without changing
which corner has the smallest clearance.

The minimum tool-face clearance is

\begin{equation}
h_{\mathrm{Tool}}(t)
=
\min_{i\in\{1,2,3,4\}}h_i(t).
\label{eq:implementation_tool_clearance}
\end{equation}

Surface Approach ends when

\begin{equation}
h_{\mathrm{Tool}}(t)\leq h_{\mathrm{clearance}},
\label{eq:implementation_clearance_transition}
\end{equation}

with \mbox{\(h_{\mathrm{clearance}}\)} the configured tool clearance of
Table~\ref{tab:experimental_phase_parameters}.

\begin{figure}[H]
  \centering
  \input{figures/tool_clearance_criterion.tex}
  \caption{Tool-face clearance criterion.}
  \label{fig:tool_clearance_criterion}
\end{figure}

\mbox{\Cref{fig:tool_clearance_criterion}} draws the criterion for an inclined
tool face. The minimum surface-normal distance \mbox{\(h_{\mathrm{Tool}}\)} is
taken from the closest tool-face corner and compared with the configured
threshold.

The trajectory is generated for
the TCP, whereas this transition is determined from the calibrated tool
geometry. Since \mbox{\(h_{\mathrm{Tool}}\)} is the minimum clearance of the
four corners, \mbox{\(h_{\mathrm{clearance}}\)} specifies the clearance of the
part of the rectangular face closest to the configured plane. At the
experimental value \mbox{\(h_{\mathrm{clearance}}=0.020\,\mathrm{m}\)}, that
part of the face is \mbox{\(20\,\mathrm{mm}\)} above the configured plane at
the transition. The criterion therefore provides a consistent tool-face
clearance for different pre-contact orientations.

At the clearance transition, the same four corner clearances determine the
geometric tool point used during Contact Establishment. Corner \mbox{\(i\)}
belongs to the selected set \mbox{\(\mathcal I_{\mathrm{sel}}\)} when its
clearance differs from the minimum clearance by no more than the selection
tolerance \mbox{\(\varepsilon_{\mathrm{sel}}\)}:

\begin{equation}
\mathcal I_{\mathrm{sel}}
=
\left\{
i\in\{1,2,3,4\}
\;\middle|\;
h_i-h_{\mathrm{Tool}}\leq\varepsilon_{\mathrm{sel}}
\right\}.
\label{eq:implementation_selected_corner_set}
\end{equation}

\mbox{\Cref{tab:calibrated_tool_geometry}} gives the selection tolerance used
in the experiments. For the rectangular tool geometry, three geometric cases
are possible, as \mbox{\Cref{fig:leading_feature_cases}} illustrates:

\begin{itemize}
  \item one selected corner: the tool point is the leading corner;
  \item two adjacent selected corners: the tool point is the midpoint of the
        leading edge;
  \item all four selected corners: the tool point is the centre of the tool
        face.
\end{itemize}

In each case, the selected tool point is obtained as the mean of the selected
corner offsets. With \mbox{\(N=\lvert\mathcal I_{\mathrm{sel}}\rvert\)},

\begin{equation}
r_{\mathrm{Tool,EE}}
=
\frac{1}{N}\sum_{i\in\mathcal I_{\mathrm{sel}}}r_{i,\mathrm{EE}}.
\label{eq:implementation_leading_feature_average}
\end{equation}

The corresponding selected tool-point position is

\begin{equation}
p_{\mathrm{Tool}}=p_{\mathrm{TCP}}+R_{\mathrm{EE}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_contact_point_position}
\end{equation}

For the tool-face-centre case,
\mbox{\(r_{\mathrm{Tool,EE}}=r_{\mathrm{face,EE}}\)}. That calibrated centre
offset lies along the end-effector \mbox{\(z\)}-axis, so the selected tool
point then lies on that axis beneath the TCP.

\begin{figure}[H]
  \centering
  \input{figures/leading_feature_cases.tex}
  \caption[Principal selected tool points for the rectangular tool face.]{%
    \Added{Principal selected tool points: (a) corner, (b) edge midpoint, and
    (c) tool-face centre.}}
  \label{fig:leading_feature_cases}
\end{figure}

At the clearance transition, the controller retains
\mbox{\(r_{\mathrm{Tool,EE}}\)} in end-effector coordinates and keeps it fixed
throughout Contact Establishment. Its base-frame representation
\mbox{\(r_{\mathrm{Tool}}=R_{\mathrm{EE}}r_{\mathrm{Tool,EE}}=p_{\mathrm{Tool}}-p_{\mathrm{TCP}}\)}
therefore follows the measured end-effector orientation.

The controller uses three distinct points in this construction. The TCP
\mbox{\(p_{\mathrm{TCP}}\)} is the Cartesian point regulated by the impedance
law. The selected tool point \mbox{\(p_{\mathrm{Tool}}\)} is the calibrated
geometric point used to generate the Contact Establishment trajectory. The
virtual \abbr{CoC} \mbox{\(p_c\)} of
\mbox{\Cref{sec:centre_of_compliance}} is the point about which the impedance
is defined, and its position is independent of the selected tool geometry.

\subsection{Operator-Controlled Hold Before Contact Establishment}
\label{subsec:implementation_pre_contact_hold}

The optional Pre-Contact Hold maintains the Cartesian pose reached at the end
of Surface Approach. After operator confirmation, the controller captures the
current measured pose and initialises the Contact Establishment references from
it.

The surface-contact experiments disabled this hold. Contact Establishment
therefore began directly at the clearance transition, and that instant also
defined \mbox{\(t_{\mathrm{CE,start}}\)}.

\subsection{Contact Establishment}
\label{subsec:implementation_setup_phase}
\label{sec:surface_frame_gains}
\label{subsec:phase_dependent_gain_construction}
\label{sec:self_alignment_virtual_center}

\paragraph{Reference capture and press trajectory.}
At the transition instant \mbox{\(t_{\mathrm{CE,start}}\)}, the controller
captures the measured end-effector orientation and TCP position:

\begin{equation}
R_{\mathrm{EE,clearance}}=R_{\mathrm{EE}}(t_{\mathrm{CE,start}}),
\qquad
p_{\mathrm{TCP,clearance}}=p_{\mathrm{TCP}}(t_{\mathrm{CE,start}}).
\label{eq:implementation_clearance_pose}
\end{equation}

Together with the retained tool-point offset
\mbox{\(r_{\mathrm{Tool,EE}}\)}, these quantities define the selected
tool-point position at the transition:

\begin{equation}
p_{\mathrm{Tool,clearance}}
=p_{\mathrm{TCP,clearance}}+R_{\mathrm{EE,clearance}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_clearance_tool_point}
\end{equation}

The controller projects this point orthogonally onto the configured surface
plane, which defines the surface reference point
\mbox{\(p_{\mathrm{Tool},0}\)}:

\begin{equation}
p_{\mathrm{Tool},0}
=p_{\mathrm{Tool,clearance}}
-n_sn_s^\top\left(p_{\mathrm{Tool,clearance}}-p_s\right).
\label{eq:implementation_projected_tool_point}
\end{equation}

That point lies on the configured reference plane directly along the
surface-normal direction from \mbox{\(p_{\mathrm{Tool,clearance}}\)}, and it is
the zero position of the Contact Establishment coordinate
\mbox{\(s_{\mathrm{CE}}\)}.

The coordinate \mbox{\(s_{\mathrm{CE}}\)} specifies the desired
selected-tool-point position relative to the configured plane along
\mbox{\(-n_s\)}. Negative values place the reference on the free-space side of
the plane, \mbox{\(s_{\mathrm{CE}}=0\)} places it on the plane, and positive
values place it on the surface side. Its initial value is

\begin{equation}
s_{\mathrm{CE}}(t_{\mathrm{CE,start}})
=
-n_s^\top\left(p_{\mathrm{Tool,clearance}}-p_s\right).
\label{eq:implementation_setup_initial_coordinate}
\end{equation}

At the clearance transition the selected point lies on the free-space side of
the configured plane, so
\mbox{\(s_{\mathrm{CE}}(t_{\mathrm{CE,start}})<0\)}. This initial value
reproduces the measured selected-tool-point position exactly, so the Cartesian
position reference is continuous when the controller enters Contact
Establishment.

The coordinate then increases at the configured press speed
\mbox{\(v_{\mathrm{CE}}\)} until it reaches the endpoint
\mbox{\(s_{\mathrm{CE,max}}\)} at \mbox{\(t_{\mathrm{CE,max}}\)}:

\begin{equation}
s_{\mathrm{CE}}(t)
=
\begin{cases}
s_{\mathrm{CE}}(t_{\mathrm{CE,start}})
+v_{\mathrm{CE}}\left(t-t_{\mathrm{CE,start}}\right),
& t_{\mathrm{CE,start}}\leq t<t_{\mathrm{CE,max}},\\[4pt]
s_{\mathrm{CE,max}}, & t\geq t_{\mathrm{CE,max}}.
\end{cases}
\label{eq:implementation_setup_press_coordinate}
\end{equation}

\mbox{\Cref{app:controller_parameters}} records the configured press speed and
endpoint. The desired selected-tool-point position is

\begin{equation}
p_{\mathrm{Tool},d}(t)
=
p_{\mathrm{Tool},0}-s_{\mathrm{CE}}(t)n_s.
\label{eq:implementation_setup_face_point_reference}
\end{equation}

Throughout Contact Establishment, the desired orientation remains fixed at the
orientation captured at the clearance transition:

\begin{equation}
R_d(t)=R_{\mathrm{EE,clearance}}.
\label{eq:implementation_setup_orientation_reference}
\end{equation}

The trajectory is defined for the selected geometric tool point, while the
Cartesian impedance law regulates the TCP. At the fixed reference orientation,
the rigid-body relation between the two points is

\begin{equation}
p_{\mathrm{Tool},d}(t)
=
p_d(t)+R_{\mathrm{EE,clearance}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_setup_rigid_body_relation}
\end{equation}

Solving for the desired TCP position gives

\begin{equation}
p_d(t)
=
p_{\mathrm{Tool},d}(t)-R_{\mathrm{EE,clearance}}r_{\mathrm{Tool,EE}}.
\label{eq:implementation_setup_tcp_reference}
\end{equation}

During the linear part of the press trajectory, the desired TCP velocity is
\mbox{\(\dot p_d=-v_{\mathrm{CE}}n_s\)}. It is zero after
\mbox{\(s_{\mathrm{CE,max}}\)} is reached.

The controller therefore defines the press at the selected geometric tool point
and calculates the corresponding TCP reference. Contact restricts the commanded
motion towards the surface, and the resulting Cartesian position error
generates the commanded pressing force. The configured endpoint lies on the
surface side of the reference plane and is a virtual Cartesian spring
reference; the contact interaction determines the actual tool motion.
\mbox{\Cref{fig:setup_reference}} summarises this reference construction.

  \caption{Contact-establishment reference generation.}

\paragraph{Active impedance.}
Contact Establishment keeps the orientation reference \mbox{\(R_d\)} fixed
while applying finite rotational stiffness. Contact forces can therefore rotate
the measured end-effector orientation away from the held reference, and the
rotational impedance generates the corresponding restoring moment.

The controller uses the same position and orientation references for the
TCP-centred and displaced-\abbr{CoC} conditions. When a virtual \abbr{CoC} is
enabled, the point-shifted stiffness and damping matrices of
\mbox{\Cref{sec:centre_of_compliance}} additionally couple the translational
press to the commanded moment. The active impedance matrix therefore changes,
while the generated Contact Establishment trajectory remains unchanged.

At the transition from Surface Approach to Contact Establishment, the
controller changes from the approach stiffness-and-damping set to the Contact
Establishment set. The directional translational and rotational matrices are
first defined in their configured frame and transformed into the robot base
frame. When a displaced \abbr{CoC} is active, the controller then applies the
point-shift transformation of \mbox{\Cref{sec:centre_of_compliance}}.

The frame used for the translational Contact Establishment gains is
configurable, and the surface-contact experiments expressed these gains in the
configured surface frame. Contact Establishment and Grinding obtain their gains
from the same configured translational and rotational source blocks. Contact
Establishment can define the impedance about a displaced virtual \abbr{CoC},
whereas Grinding defines it at the TCP and uses a different Cartesian reference
generator.
Contact-Impedance Hold can temporarily apply its dedicated hold stiffness and
damping while maintaining the captured Cartesian reference.
\mbox{\Cref{ch:methodology}} reports the numerical values used in the
experiments.

\paragraph{Inertia-scaled damping.}
For controller states that use inertia-scaled damping, the directional damping
coefficients are calculated according to
\mbox{\Cref{eq:inertia_scaled_damping}}. The controller obtains the joint-space
inertia \mbox{\(M(q)\)} and the Jacobian \mbox{\(J(q)\)} from the libfranka
model. An \mbox{\abbr{LDLT}} factorisation evaluates the required system while
leaving \mbox{\(M(q)^{-1}\)} implicit.

The controller stores the resulting damping matrix for each
stiffness-and-damping configuration and recalculates it when that configuration
is activated. \mbox{\Cref{app:controller_parameters}} reports the coefficient
bounds, the validity checks, and the fallback damping matrices. The
surface-contact experiments used inertia-scaled damping during Surface Approach
and Contact Establishment.

\paragraph{Centre-of-compliance implementation.}
The controller implements the point shift of
\mbox{\Cref{sec:centre_of_compliance}} using
\mbox{\(r_c=p_c-p_{\mathrm{TCP}}\)}. Two definitions of the displacement
are supported, because the frame in which its components stay fixed determines
its behaviour during end-effector rotation.

For a tool-fixed displacement, the configured components
\mbox{\(r_{c,\mathrm{EE}}\)} remain constant in the end-effector frame, and the
controller transforms them into base coordinates in every callback,
\mbox{\(r_c=R_{\mathrm{EE}}r_{c,\mathrm{EE}}\)}. The base-frame
displacement therefore rotates with the end effector.

For a surface-fixed displacement, the components \mbox{\(r_{c,S}\)} remain
constant in the configured surface frame, so
\mbox{\(r_c=R_{\mathrm{surface}}r_{c,S}\)}. The surface frame stays fixed
during a controller session, so this base-frame displacement remains constant
during Contact Establishment. When the virtual \abbr{CoC} is enabled, the
configuration accepts exactly one of the two definitions. All non-zero
\abbr{CoC} displacements used in the experiments were tool-fixed.

The controller assembles the translational and rotational source matrices into
the block-diagonal stiffness \mbox{\(K_c\)} and damping \mbox{\(D_c\)} at the
virtual \abbr{CoC}. It then maps these matrices to the TCP through the
congruence transformations of
\mbox{\Cref{eq:coupled_tcp_stiffness,eq:coupled_tcp_damping}}.

For a tool-fixed displacement, a change in \mbox{\(R_{\mathrm{EE}}\)} changes
\mbox{\(r_c\)}, so the controller updates the shifted base-frame matrices
in every control cycle. For a surface-fixed displacement, the shifted matrices
remain constant while the source matrices are unchanged. Setting
\mbox{\(r_c=0\)} makes the point-shift adjoint the identity and recovers the
decoupled block-diagonal impedance at the TCP.

During Contact Establishment, the displaced \abbr{CoC} allows the commanded
normal press to contribute to the rotational response.
\mbox{\Cref{ch:results_discussion}} evaluates the resulting influence of the
tangential \abbr{CoC} position.

\paragraph{Termination.}
At the clearance transition, the controller stores the model-estimated external
wrench supplied by libfranka. After the configured minimum Contact
Establishment duration, the state can end when the change in the estimated
external moment exceeds the configured threshold. The independent timeout
supplies the alternative transition. Every surface-contact experiment reached
the timeout transition.


\subsection{Operator-Controlled Hold Before Grinding}
\label{subsec:implementation_pre_grinding_hold}

Pre-Grinding Hold begins when Contact Establishment satisfies the moment-change
condition after its minimum duration, or reaches its independent timeout. The
final Contact Establishment position and orientation references are retained,
while the Cartesian impedance controller remains active. The controller
therefore continues to generate the corresponding force and moment commands
while waiting for operator confirmation.

If the physical surface orientation is changed manually during the hold, the
resulting contact moment can rotate the tool against the finite rotational
impedance, allowing the tool to follow the changed surface orientation while
the commanded reference remains fixed. For \mbox{\(r_c=0\)}, the translational
and rotational impedance are decoupled at the TCP, so the normal pressing force
introduces no additional \abbr{CoC}-induced moment. The response therefore has
no preferred rotational direction from the virtual \abbr{CoC}.

Operator confirmation then initiates Grinding.

\section{Cartesian Pose Hold}
\label{subsec:implementation_pose_hold}
\label{sec:nullspace_conditioning_implementation}

Cartesian Pose Hold begins after the robot reaches the stored initial joint
configuration \mbox{\(q_{\mathrm{init}}\)}, or from the current guided
configuration \mbox{\(q\)} when the operator types \texttt{h} in Manual
Guidance. At state entry \mbox{\(t_0\)}, the controller captures
\mbox{\(p_d=p_{\mathrm{EE}}(t_0)\)} and
\mbox{\(R_d=R_{\mathrm{EE}}(t_0)\)}, and maintains these references with a
dedicated hold impedance expressed in the base frame.

Four null-space modes can be selected without changing the Cartesian
reference:

\begin{itemize}
  \item Mode 0 applies no null-space torque.
  \item Mode 1 applies projected damping, with
        \mbox{\(d_{\mathrm{null}}\)} adjustable.
  \item Mode 2 applies singular-value conditioning, with
        \mbox{\(k_\sigma\)} adjustable.
  \item Mode 3 applies both terms together, with both parameters adjustable.
\end{itemize}

Entering another number switches modes while the Cartesian reference and
impedance remain unchanged. Contact-Impedance Hold is a separate controller
state outside these four modes.

\begin{figure}[H]
    \centering
    \input{figures/pose_hold_modes.tex}
    \caption{Operator-selectable null-space modes in Cartesian Pose Hold.}
    \label{fig:pose_hold_modes}
\end{figure}

The implementation specifies two numerical choices beyond
\mbox{\Cref{sec:nullspace_svd}}. The pseudoinverse threshold is the configured
relative tolerance multiplied by the largest current singular value. The
resulting joint-torque projector is symmetrised numerically, and the
controller reuses that same projector to calculate the logged projected joint
velocity \mbox{\(\dot q_{\mathrm{null}}\)}. For singular-value
conditioning, the controller evaluates the Jacobian at
\mbox{\(q\pm\alpha_{\mathrm{probe}}v_7\)} using the current robot
transformations, and compares the smallest singular value at each probe. The
configured deadband sets the conditioning torque to zero.


\section{Robot-Side Safety and Command Handling}
\label{sec:collision_behavior_safety}
\label{subsec:robot_collision_configuration}
\label{subsec:initial_joint_posture}
\label{subsec:controller_exception_handling}

The complete joint-torque command of
\mbox{\Cref{eq:nullspace_complete_torque_command}} is returned directly to
libfranka. The configured robot-side collision and reflex monitoring provide
the protection layer used during the experiments. Its joint-torque and
Cartesian-wrench thresholds are recorded in
\mbox{\Cref{subsec:reproducibility_record}}. A robot communication,
motion-generation or torque-control error leaves the callback through
\mbox{\texttt{franka::Exception}} and ends the control session.

A libfranka joint-motion generator brings the robot to the configured initial
posture before torque control starts, unless the experiment starts from a pose
captured after Manual Guidance. The posture used in the experiments is recorded
in \mbox{\Cref{app:controller_parameters}}. Operator input and file writing
remain outside the real-time thread, and the torque callback operates only on
prepared in-memory data.


\section{Real-Time Data Recording}
\label{sec:recorded_signals}
\label{subsec:chronological_log_output}
\label{subsec:setup_run_evaluation}

During torque control, the controller stores the experimental signals in a
preallocated, fixed-capacity in-memory ring buffer. Each row carries the
measured state, the active Cartesian reference, the calculated pose error and
wrench, the controller state, the null-space configuration, and the returned
joint torque. When the allocated capacity is reached, the write index wraps and
new rows replace the oldest. After torque control ends, the remaining buffer
contents are written to the \mbox{\abbr{CSV}} file in chronological order.
